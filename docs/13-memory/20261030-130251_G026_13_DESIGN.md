# G026-13 — 간식 짝꿍 / buildable design v1.0

Authority: G026_PM_CONTRACT.md plus read-only original13. Primary loop: reveal, remember, pair. No character/costumes, adversarial opponent or countdown.

## Rules and pure engine
- Modes `easy` = 3 columns x4 rows/6 pairs; `normal` =4x4/8 pairs, default normal. All 8 SVG snack IDs fixed (`apple`, `pear`, `orange`, `berry`, `cookie`, `bread`, `cherry`, `candy`), easy uses first6. Every deck contains each selected ID exactly twice.
- Inject RNG into unbiased descending Fisher-Yates shuffle. For each call require primitive number finite 0<=r<1; invalid return or exception makes deck creation fail atomically (no partial state/attempts/round consumed). UI provides retryable error and remains ready/current paused state intact; no empty or biased fallback deck. Unit test 0 and near1 and invalid values.
- State contains cards with unique position/index, revealed and matched flags, firstIndex|null, mismatchIndices|null, mismatchRemainingMs, attempts, matchedPairs, activeElapsedMs, firstFlipStarted, phase, roundId. Input indices must be primitive integers in range. Invalid type (including symbols/coercion-throwing object), repeated same open card, matched card, hidden/input locked/paused/result operations return exact same state and do not consume RNG/timing/counters/feedback.
- Start creates a fresh shuffled deck, all closed. Timer starts only on first valid reveal. Second distinct card increments attempts exactly1 synchronously. If same ID: mark both matched, clear first selection; if all pairs matched, success synchronously and settle once, winning cards remain visible. Otherwise immediate next selection allowed; optional visual matched flash never owns state.
- On mismatch: both visible, lock all other reveals, active-time countdown exactly800ms; advance(799) remains open, plus1 closes both/clears first/unlocks. Timer continues during mismatch while playing. Pause freezes elapsed and remaining delay, cancel pending RAF/timer; resume uses remaining delay (not fresh800 and not wall time). Restart invalidates all old-round pending work. No unpausing modal can run the old timer.
- UI pumps from performance.now in active foreground; steps <=250ms, arrival gap>250ms protection-pauses before applying time. Never use stale RAF timestamp as arrival clock. Pure engine advance accepts primitive finite nonnegative elapsed<=250 only; invalid or oversized dt exact no-op, no coercion. Test800 through valid steps.
- MAX_ATTEMPTS=999999; maximum active elapsed=86400000ms (24h). On comparison that reaches attempt cap, allow resulting all-matched success priority; otherwise end `limit` with no best update. Time cap similarly ends `limit`; no NaN/overflow. Success elapsed stored as max(1,floor(activeElapsedMs)); nonfinal fractions may be kept internally but cap safely.

## Outcomes and records
- No normal failure/time pressure. Success result: pairs, attempts, active time, best comparison. Abandon/restart/home never stores successful completion. `limit` is protective termination, not success.
- Compare per-mode best lexicographically: fewer attempts first, then lower integer elapsedMs; exact tie displays tie and preserves previous best. Worse time with fewer attempts still wins. No combined score invented.
- Storage shape `{version:1, settings:{mode,theme,muted}, modes:{easy:{completions,best},normal:{completions,best}}}`. Theme cream/meadow/evening, muted boolean. completions integer0..1000000, best null iff completions0; nonnull best attempts in[pairs,999999], elapsedMs in[1,86400000]. On cap completions remains1000000 but best may improve. Each mode invalid record resets just that mode; valid other mode/settings retained, warning. Unknown properties ignored without affecting controls. Partial settings restore independently, unknown mode normal/theme cream/muted true.
- Record settlement exactly once per round. Retry Start/result/keypress duplication cannot store twice. Settings preview does not write; Apply one write. Switching mode while active requires explicit abandonment confirmation; apply only after confirmation and return ready/new mode, not an automatic first reveal. Cancelling mode change keeps deck/attempts/time/mode.

## Interface and assets
- Header `간식 짝꿍`, mode and theme buttons/help/mute/home. Metrics `찾은 쌍`, `시도`, `시간`; center4x4 or3x4. Primary Start / Pause / explicit Resume, Restart. Best record and instruction separate from live status.
- Open card uses original SVG plus Korean text; closed accessible label `N번 카드, 닫힘` must NOT expose snack; opened `N번 카드, 사과, 열림`, matched includes `짝 완료`. Matched border/check marker. Do not use aria-hidden on focusable card. Native button input only; no dragging or hold action. Roving optional but Tab/Enter baseline must work.
- Art manifest/provenance in implementation handoff:8 SVG fronts and3 backs (or one self-contained sprite with exact8+3 IDs), no external refs/script; readable at44px minimum, central illustration not obscure label. Flip <=120ms visual only, reduced motion none; 800ms comparison always.
- Viewport320: main padding12, card4x[(available board width-18 gap)/4], each>=44; no horizontal scroll necessary. Dialogs scroll at320x480. Ready/playing/mismatch/paused/result/storage-error each has meaningful text; hiding board faces during protection pause prevents comparing while time stopped (restore exact revealed cards on resume).
