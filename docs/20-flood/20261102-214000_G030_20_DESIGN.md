## 0. 한눈에 보기

1. 판은 `size×size` 격자, 칸마다 색 번호. 왼쪽 위 칸(0번)과 상하좌우로 이어진 같은 색 칸이 **내 영역**.
2. 색 버튼을 누르면 내 영역 전체가 그 색으로 바뀌고, 새로 닿은 같은 색 칸이 연쇄로 흡수됩니다. 대각선은 연결이 아닙니다.
3. 판 전체가 내 영역이면 승리, 정해진 횟수를 다 쓰고도 아니면 패배. 마지막 수에서는 승리 검사가 먼저입니다.
4. 같은 색 재선택은 횟수 불변, 다른 색 선택은 영역이 안 커져도 1회.
5. 입문 6×6·3색 5판(1~5단계), 기본 8×8·4색 10판(6~15단계), 고정 맵. 제한 횟수 = 솔버가 찾은 해결 경로 길이 + 3.
6. 점수 = 남은 횟수 × 100. 같은 단계에서는 사용 횟수가 적은 기록이 우선. 완료 기록과 해금만 저장.
7. 타이머·물리·논리 잠금이 없습니다(G029 17/18의 120/200ms 잠금과 다름). 번짐 연출은 CSS 전환이며 판정과 무관합니다.

## 1. 규칙

### 1.1 용어와 상태

| 항목 | 정의 |
|---|---|
| `size` | 한 변 칸 수. 입문 6, 기본 8 |
| `colors` | 색 수 k. 입문 3, 기본 4. 색 번호 0..k-1, 화면 번호·숫자키는 번호+1 |
| `cells` | 길이 size² 의 원래 색 배열(행 우선, 인덱스 `r*size+c`), 단계마다 불변 |
| `region` | 내 영역의 칸 집합. 항상 0번 칸을 포함하고 상하좌우로 연결 |
| `currentColor` | 내 영역의 현재 색. 시작 시 `cells[0]` |
| `used` / `limit` / `remaining` | 센 횟수 / 제한 횟수 / `limit-used` |
| 표시 색 | `region`에 속한 칸은 `currentColor`, 그 외는 `cells` 원래 색 |

### 1.2 시작 영역

- 시작 영역 = 0번 칸에서 `cells[0]`과 같은 색의 상하좌우 연결 성분 전체. `used=0`, `currentColor=cells[0]`.
- 모든 맵은 시작 영역이 판 전체가 아니고(단색 시작·이미 완성 금지) 모든 색이 판에 존재합니다(3절).

### 1.3 색 선택 처리 순서(엔진은 이 순서를 지킵니다. 한 번의 호출에서 원자적으로 끝나며 타이머·애니메이션 콜백에 의존하지 않음)

`pick(state, c)`:

1. `phase !== 'playing'`이거나 `c`가 정수가 아니거나 `0 <= c < colors` 밖이면 **무시**(상태·횟수·기록 불변, 기록 쓰기 없음).
2. `c === currentColor`이면 **같은 색 재선택**: `used`·영역·기록 모두 불변. 화면에는 "이미 ○○이에요. 횟수는 그대로예요." 안내만(읽기 전용 `lastEvent.kind='same-color'`). 소리 없음. 결과로 넘어가지 않음.
3. 그 밖의 `c`(다른 색)는 **유효한 선택**: `used += 1`, `currentColor = c`, 내 영역에서 시작해 `c` 색의 이웃 칸을 더 이상 없을 때까지 흡수(상하좌우 4방향, 흡수된 칸의 이웃도 연쇄). 새로 흡수된 칸이 0개여도(영역이 안 커져도) `used`는 1 증가합니다. 판에서 이미 모두 사라진 색을 골라도 마찬가지로 1회입니다.
4. 3 이후, `region`이 전체 칸이면 `phase='result'`, `outcome='win'`, `score=(limit-used)*100`. **이 검사가 먼저입니다.**
5. 4가 아니고 `used >= limit`이면 `phase='result'`, `outcome='lose'`. (`used`가 `limit`을 넘는 상태는 없음.)
6. 둘 다 아니면 `playing` 유지.

마지막 허용 수(`used==limit`)에서 영역이 전체가 되면 4에서 승리이며 점수 0, 남은 횟수 0의 **유효한 완료**입니다.

### 1.4 그 밖의 규칙

- 되돌리기 없음(원안에 없음). 다시 시작은 같은 맵·같은 시작 영역·`used=0`으로 새 라운드를 시작합니다(진행 중이면 확인 필수).
- 결과(`result`)에서는 색 선택이 모두 무시됩니다.
- 같은 색을 빠르게 두 번 눌러도(더블탭) 두 번째는 무료입니다. 서로 다른 색을 빠르게 연타하면 입력마다 1회로 셉니다(잠금 없음, 의도한 입력은 모두 처리).
- 승리 점수의 범위는 모든 맵에서 0~300(최대 300 = 해결 경로 길이로 끝낸 경우).

### 3.2 난이도 곡선과 제한 횟수

- 경로 길이 4→8(입문), 8→13(기본)으로 점진 증가. 제한 횟수는 7~16.
- 참고 지표(`artifacts/g030-design20/greedy.log`, 규칙 아님): "한 번에 가장 많이 흡수하는 색" 탐욕법도 15개 모두 제한 안에 해결(길이 4~15). 20,000회 무작위 플레이(다른 색 균등)의 성공률은 입문 32~73%, 기본 0.7~7.5%. 입문이 쉽고 기본에서 숙련이 필요하도록 의도했습니다. 사람이 느끼는 난이도·시간은 미검증이며 PM 판단 사항입니다.

### 3.3 "해결 경로"와 제한 횟수의 표기 규칙

- 화면·도움말·결과·식별자·저장 필드 어디에도 "최적해", "최소 횟수", `optimal`을 쓰지 않습니다. 사용 가능한 표현은 "제한 횟수", "해결 경로(데이터 필드 `path`/`pathLength`)", "남은 횟수".
- 사실관계: 이번 15개 맵은 전수 BFS와 다른 구현(깊이 제한 탐색)이 모두 같은 최소 길이를 냈습니다(`verify.log`). 그래도 UI는 이를 주장하지 않고, 저장 검증의 하한(5.3)에만 내부적으로 사용합니다. 하한이 불편하면 5.3의 `pathLength`를 `1`로 완화할 수 있습니다(가정 8).

### 3.4 맵 생성·검증 방법(재현 가능한 절차)

1. 단계 `id`마다 시드 `20261102 + id×7919`의 mulberry32 난수로 색을 균등 추출해 격자를 만듭니다.
2. 후보 거절 조건(모두 만족해야 채택):
   - 모든 색이 존재하고 각 색 칸 수 ≥ ⌈size²/k × 0.6⌉.
   - 시작 영역이 전체가 아님(단색·이미 완성 금지) 그리고 시작 영역 ≤ 4칸.
   - 솔버 최소 경로 길이가 단계별 목표 `[4,5,6,7,8,8,9,9,10,10,11,11,12,12,13]`와 같음.
   - **중복 금지**: 색 번호를 첫 등장 순서로 다시 매긴(정규화) 문자열이 다른 단계와 같지 않고, 전치(행↔열)한 판의 정규화 문자열도 같지 않음.
3. 솔버: 영역 비트마스크 + 현재 색을 상태로 하는 BFS(정확한 최소 길이와 경로). 교차 검증: 배열 flood + 깊이 제한 DFS(남은 색 종류 수 ≤ 남은 횟수 가지치기, 전치표)가 `길이-1`에서 실패하고 `길이`에서 성공.
4. 경로를 독립 flood 구현으로 재생해 마지막 수에서만 완성되는지 확인.
5. 실행 결과: 15개 모두 PASS(`verify.log`, `ALL PASS`). 시도 횟수는 단계 1이 1회, 15단계가 5105회까지 소요(생성은 1초 미만).

### 3.6 금지 규칙(단위 시험 대상)

- 단계 간 `cells` 중복(정규화·전치 포함) 금지.
- 시작판이 이미 완성이거나 단색인 단계 금지. 색 일부가 판에 없는 단계 금지.
- `limit == pathLength + 3` 불변, `path`를 재생하면 `pathLength`번째 수에서 처음 완성(그 전에는 미완성).
- 크기·색 수는 1~5단계 6/3, 6~15단계 8/4.

## 4. 점수와 기록

- 승리 점수 `score = (limit - used) × 100` (0~300). 패배는 점수 없음.
- 같은 단계의 비교는 **사용 횟수가 적은 쪽이 우선**. 단계마다 `limit`이 고정이므로 사용 횟수가 적으면 점수도 높고 두 값은 항상 `score=(limit-used)*100` 관계입니다.
- 결과 화면 기록 판정: 첫 완료 또는 `used < 이전 bestUsed` → "새 최고 기록", `==` → "최고 기록과 같아요", `>` → 최고 기록 표시. 이 판정은 정산 시 한 번 계산해 결과에 표시합니다.
- 누적 총점은 만들지 않습니다(원안: 클리어 횟수·사용 횟수·남은 횟수 점수만).

## 5. 저장·정산

### 5.1 정산 시점과 쓰기 정책

- 쓰기는 오직 (a) 승리 결과의 **최초 1회 정산**, (b) 명시적 설정 변경(테마 적용으로 값이 바뀔 때, 소리 토글)에서만 발생합니다.
- 읽기, 준비, 단계 선택, 시작, 같은 색 재선택, 일시정지·재개, 모달 열기·취소, 다시 시작, 포기, 패배, 홈 이동은 **쓰기 0회**.
- 패배는 저장하지 않습니다(가정 2). 진행 중 판은 저장하지 않으며 새로고침하면 사라집니다.
- 정산은 라운드 번호(`round`) 기준으로 1회입니다. 결과 화면 재렌더, 모달 열기·닫기, 정지·재개, 창 복귀로 중복 정산하지 않습니다. 결과 상태에서 `settledRound === round`.

```
    completed: 0..1_000_000,                  // 모든 단계 clearCount의 합(파생값과 일치해야 함)
    unlocked: 1..15,                          // 선형 해금(가정 1)
    stages: [ 15개 × { clearCount: 0..1_000_000, bestUsed: int|null, bestScore: int|null } ]
  } }
```

기본값: theme `paint`, muted `true`, completed 0, unlocked 1, 모든 단계 `{0, null, null}`.

### 5.3 검증과 복구(`recoverRecord`)

- 최상위가 객체가 아니거나 `version !== 1`이면 전체 기본값 + 복구 경고.
- `settings.theme`이 목록 밖이면 theme만 기본값, `muted`가 boolean이 아니면 muted만 기본값. **불량 설정 때문에 유효한 완료 기록을 지우지 않습니다.**
- 단계별 독립 검증: `clearCount`는 0..CAP의 safe integer. `clearCount==0`이면 `bestUsed==null && bestScore==null`. `>0`이면 `bestUsed`는 safe integer이고 `pathLength <= bestUsed <= limit`(해당 단계의 데이터), `bestScore === (limit - bestUsed) × 100`. 배열 길이가 15가 아니거나 항목이 불량이면 **그 단계만** 기본값(경고).
- `completed`와 `unlocked`는 유효한 단계 기록에서 **파생**합니다: `completed = Σ clearCount`(누적이 CAP을 넘는 단계는 불량 처리), `unlocked = max(1, min(15, clearCount>0인 최대 단계 id + 1))`. 저장값과 다르면 경고 후 파생값 사용.
- primitive/배열/null/NaN/Infinity/음수/unsafe integer/문자열 숫자는 모두 불량. JSON 파싱 실패는 전체 기본값 + 경고.
- 읽기 중 `getItem`/`localStorage` getter 예외는 아래 5.5의 메모리 모드.

### 5.4 정산 함수 `settleRecord(record, result)` 계약

- 입력 `result={stageId, used, score}` 검증: `stageId` 1..15, `used`는 `pathLength..limit`의 정수, `score === (limit-used)*100`. 불량이면 **record 그대로 반환(참조 동일)** 하고 `rejected`.
- 포화: 해당 단계 `clearCount >= CAP` 또는 `completed >= CAP`이면 **어떤 필드도 바꾸지 않고** record 그대로 + `capped`. (bestUsed/bestScore/clearCount/completed/unlocked 중 일부만 증가 금지.)
- 정상: `clearCount+1`, `completed+1`, `bestUsed=min`, `bestScore=max`, `unlocked=max(unlocked, min(15, stageId+1))`. 새 객체 반환(입력 불변), 판정 `new-best|tie|not-best`.
- 같은 라운드의 재호출은 UI가 막습니다(`settledRound`). 엔진 함수 자체는 순수.

### 5.5 저장 실패·경고 문구 규칙(G029 교훈 3)

- `getItem`/`localStorage` getter 예외: **메모리 모드**. 기록은 이번 페이지에서만 유지하며 **그 세션에서는 쓰기를 시도하지 않습니다**(읽지 못한 기존 유효 기록을 덮어쓰지 않기 위해, 가정 7). 지속 경고: "저장소를 읽지 못했어요. 이번 페이지에서만 기록이 유지돼요."
- `setItem` 예외·차단·용량 초과: 메모리 갱신은 유지, 지속 경고 "저장하지 못했어요. 이번 페이지 기록은 유지되지만 새로고침하면 사라질 수 있어요." 다음 쓰기 트리거에서 `setItem`이 성공하면 이 경고를 **해제**합니다.
- 복구 안내(손상 JSON, 불량 설정, 단계 기록 일부 복구): 정보성 경고. 이후 쓰기가 성공하면 해제.
- **"저장했어요/기록에 반영했어요" 문구는 직전 쓰기가 실제로 성공했을 때만** 사용합니다. 저장 실패·메모리 모드·포화에서는 사용 금지. 결과 화면의 기록 줄은 저장 상태를 따릅니다: 성공 → "기록에 저장했어요", 실패/메모리 → "이번 페이지에서만 유지돼요", 포화 → "기록 한도에 도달해 이번 결과는 기록에 더하지 않았어요". 경고 배너가 보이는 동안 결과 문구가 정반대로 말하면 안 됩니다.
- 결과 화면의 "최고 기록" 줄은 실제 `record`(메모리 값)를 표시하되 포화 시 갱신하지 않은 값 그대로입니다.
- 다른 `localStorage` 키는 읽지도 쓰지도 않습니다(자기 키만).

| 입력 | 동작 |
|---|---|
| 색 버튼 클릭/탭 | 그 색 선택(1.3) |
| 숫자 `1`~`4` (일반 키) | 색 번호 N-1 선택. 3색 단계에서 `4`는 무시(키 소비 안 함) |
| `←` `→` (색 버튼 초점 중) | 이웃 색 버튼으로 초점 이동, 가장자리에서 멈춤(순환 없음). `Home`/`End`는 첫/마지막 |
| `Tab`/`Shift+Tab` | 색 버튼 4개를 포함한 모든 조작 요소를 순서대로 |
| `Enter`/`Space` (색 버튼 초점 중) | 네이티브 버튼 활성화 = 색 선택, 자동 반복 무시 |
| `Esc` | 모달이면 닫기(확인 실행 금지), 플레이 중이며 초점이 게임 영역이면 일시정지, 그 외 아무것도 안 함 |

- 보드 칸은 조작 대상이 아닙니다(칸 클릭으로 색을 고르는 원작 방식은 쓰지 않음, 가정 4). 따라서 칸에는 44px 요건이 없고 보드는 정보 표시 전용입니다.
- 숫자키는 `visible && phase==='playing' && 모달 없음 && 수정자 키 없음 && 초점이 body 또는 게임 영역(main) 안 && 초점이 입력 필드/선택 상자가 아님 && !e.repeat && 해당 키가 아직 눌린 상태로 기록돼 있지 않음`일 때만 처리합니다. 처리하지 않는 키는 `preventDefault` 하지 않습니다(외부 키 소비 금지).
- `keyup`/blur/상태 전이 시 눌린 키 기록을 비웁니다.

### 6.1 포인터 제스처(색 버튼 포함 모든 버튼·링크, G029 공통 계약 + 교훈 1·2)

- **탭 성립**: 단일 주 포인터가 같은 컨트롤에서 누르고 떼며 이동 ≤ 8px. 실제 누름 80ms 이상이 정상 동작해야 합니다(순간 클릭만 허용하는 구현 금지).
- **취소**: 스크롤, 드래그(8px 초과), `pointercancel`, `lostpointercapture`, 두 번째 포인터(보드 밖 포함). 취소된 제스처 뒤의 합성 `click`은 억제합니다.
- 캡처 단계 click 게이트: `detail > 0`(포인터 기원) click은 직전에 유효 탭이 성립해 소비되지 않은 경우(≤700ms)에만 통과. 통과한 click은 **초점 요건 없이** 처리합니다(WebKit/Safari는 클릭한 버튼에 초점을 주지 않음. 17번 D1 재발 방지).
- `detail === 0` click(키보드 Enter/Space의 네이티브 활성화, 보조기기 `.click()`): **그 버튼에 초점이 있을 때만** 처리(키보드 합성 click에만 초점 가드). 단, 취소된 제스처 직후 ≤300ms 안에 도착한 `detail 0` click은 억제합니다. 최근 1,000ms 안에 Enter/Space `keydown`을 본 click은 이 억제의 예외(키보드 사용자 보호).
- **억제 상태의 해제 경로(18번 `suppressClick` 영구 억제 재발 방지)**: 모든 억제 상태는 (a) 시각 비교 만료(제스처 취소 후 ≤300ms, 유효 탭은 ≤700ms), (b) 다음 `pointerdown` 시작 시 초기화, (c) 상태 전이·모달 열고 닫기·보호정지·`pagehide`에서 초기화 중 하나로 반드시 풀립니다. 타이머(`setTimeout`)에 의존하지 않고 `performance.now()` 비교로 구현해, 정지·숨김 중에도 억제가 남아 이후 정상 입력을 막지 않습니다.
- 눌림 상태(`:active` 표현)는 CSS로만 하고, 포인터 이벤트마다 같은 텍스트·속성을 재기록하지 않습니다.

## 7. 시각 피드백

### 7.1 현재 영역 테두리

- 내 영역 칸의 **노출된 변**(상하좌우 중 이웃이 영역이 아니거나 보드 바깥인 변)에 이중선 테두리: 바깥 2px 잉크 `#263c40` + 안쪽 2px 흰색. 어느 팔레트·어느 칸 색 위에서도 3:1 이상 보이게 합니다. 영역 안쪽 접합 변에는 테두리 없음. 판 전체가 영역이 되면 보드 가장자리를 두른 테두리가 "완성 윤곽"이 됩니다.
- 색에만 의존하지 않는 영역 표시: 테두리 + 칸의 `aria-label`("내 영역"). 보드 아래 범례 "굵은 테두리 안이 지금 내 영역이에요."
- 테두리는 CSS 클래스(예: `e-t e-r e-b e-l`)와 `::after`로 구현하고, 선택 후 영역이 바뀐 칸만 갱신합니다.

### 7.2 200ms 번짐 효과

- 색 선택 시 **바뀐 칸**(기존 영역 + 새 흡수 칸)의 배경색 `transition: background-color 120ms`. 새로 흡수된 칸은 기존 영역 경계에서 떨어진 정도(고리 `ring` 1..8, 8 초과는 8)만큼 `transition-delay = ring×10ms`(최대 80ms)를 줘 번지는 느낌을 냅니다. 총 길이 최대 200ms(= 120 + 80). 기존 영역 칸은 지연 0.
- `ring-N` 클래스는 선택 시에 붙이고 다음 선택·시작·재개·테마 변경 때 제거합니다(타이머 사용 안 함, 정지 중 남아도 무해).
- **논리와 무관**: 판정·횟수·결과·입력 수용은 번짐이 끝나기 전에 이미 확정되며, 번짐 중에도 다음 입력을 받습니다. 번짐 콜백(`transitionend`)에 규칙을 의존시키지 않습니다. 결과 패널은 판정 즉시 표시되고 보드는 가리지 않습니다.
- **reduced-motion**: `@media (prefers-reduced-motion: reduce)`에서 전환·지연 0(즉시 변경). 판정·횟수·결과는 동일.
- 상시 RAF 없음. 정지 중에는 화면 갱신이 필요 없습니다.

## 8. 상태기계와 정지

### 8.1 상태

`phase`: `ready | playing | paused | result`. `pauseCause`: `null | 'manual' | 'protection' | 'modal'`(phase가 paused일 때만 non-null). 추가 플래그 `pendingProtection`(모달 중 blur/hidden 발생 기억).

```
ready --시작--> playing --pick: 완성--> result(win)
                   |  \--pick: used==limit & 미완성--> result(lose)
                   |--일시정지/Esc--> paused(manual) --재개--> playing
                   |--blur/hidden/pagehide--> paused(protection) --재개--> playing
                   |--모달 열기--> paused(modal) --닫기--> paused(modal 또는 protection)
result --다시 도전/다음 단계--> playing (새 round)
result --단계 선택--> ready
playing|paused --처음부터(확인)--> playing (새 round, 같은 맵)
```

- 준비 → 플레이는 **명시적 `게임 시작` 버튼**(또는 결과의 다음 단계/다시 도전)에서만. 단계 선택 자체는 시작이 아닙니다.
- 준비에서는 선택한 단계의 시작 보드를 읽기 전용 미리보기로 보여주고 색 버튼은 비활성입니다.
- 해금되지 않은 단계는 선택할 수 없습니다.

### 8.2 정지 규칙

- 도움말·테마(설정)·진행 중 홈 이동 확인·처음부터 확인은 **먼저 정지**(`paused/modal`)한 뒤 모달을 엽니다. 준비/결과에서 여는 모달은 정지 상태를 만들지 않고 입력만 막습니다.
- 모달 취소/닫기는 정지로 복귀합니다. **재개는 명시적 버튼만**입니다(자동 재개 없음).
- 이미 정지 중에 모달을 열면 `pauseCause`는 모달을 닫을 때까지 유지, 닫은 뒤 원래 정지로 복귀(단 `pendingProtection`이면 `protection`으로 승격).
- `blur`/`visibilitychange(hidden)`/`pagehide`: 플레이 중이면 보호정지(`protection`). 모달이 열려 있으면 모달을 유지하고 `pendingProtection=true`, 모달을 닫으면 `protection`으로 정지. `pendingProtection`은 닫기·phase 변경·재개 시 반드시 초기화(영구 플래그 금지).
- 재개 버튼 문구: `manual` → "이어서하기", `protection`/`modal` → "게임 재개". 재개는 `modalKind`가 열려 있거나 `document.hidden`이면 무시.
- 재개/전이마다 눌린 키·제스처 기록 초기화, 재개 후 초점은 직전 초점 색 버튼(없으면 첫 버튼).
- 진행 중 포기(홈, 처음부터 확정, 단계 변경)는 기록을 정산하지 않습니다.
- 이 게임에는 논리 잠금시간과 RAF가 없으므로 "잠금 시간 동결"과 "긴 RAF delta>250ms 보호정지"는 해당 없음입니다(QA는 해당 없음으로 표시하되 RAF 상시 구동이 없음을 MutationObserver로 확인).

### 8.3 결과

- 승리 결과: 큰 제목("전부 번졌어요!"), 점수, `사용 N / 제한 L`, 남은 횟수, 기록 판정(5.5 문구 규칙), 단계 최고. 버튼: `다음 단계`(15단계에서는 숨김, "열다섯 판 모두 완성했어요" 완료 문구), `다시 도전`, `단계 선택`, `홈으로`.
- 패배 결과: "횟수를 모두 썼어요", 아직 영역 밖에 남은 칸 수, 버튼 `다시 도전`, `단계 선택`, `홈으로`(다음 단계 없음).
- 결과 진입 시 초점은 결과 패널의 주 버튼(승리 시 `다음 단계`, 아니면 `다시 도전`)으로 이동. 이때 키를 누르고 있어도 새 버튼이 반복 활성화되면 안 됩니다(`e.repeat`/눌린 키 기록으로 차단).

## 9. 설정과 테마

- 설정은 `theme: 'paint' | 'pastel'`, `muted`. 테마는 **칸·버튼 팔레트 외형만** 바꾸며 규칙·맵·문양·판정·기록은 불변입니다.
- 테마 선택은 모달에서 미리 선택 후 `적용`(값이 바뀔 때만 쓰기), `취소`는 변경 없음. 소리 토글은 즉시 저장. 소리 기본 꺼짐.
- 진행 중 테마 모달을 열면 먼저 정지(8.2).

## 11. 접근성

- 모든 색 정보는 **색 + 문양 + 숫자 + 이름**으로 중복 표시합니다. 색 버튼: 안에 큰 문양과 숫자(1~4) 표시, `aria-label` 예 "1번 주홍 원, 선택하면 내 영역이 주홍색으로 바뀌어요" , 현재 색 버튼은 `aria-pressed="true"`와 문구 "지금 색". 숫자는 스크린리더 중복을 피해 `aria-hidden`.
- 보드 칸의 문양은 모든 칸 중앙에 크게(칸의 약 55%) 표시(CSS `::before` 도형: 원 `border-radius:50%`, 사각, 삼각 `clip-path`, 마름모 `clip-path`). 텍스트 노드가 없어 RAF·선택 때 텍스트 재기록이 없습니다.
- 보드 컨테이너 `role="grid"`(행 `role="row"`, 칸 `role="gridcell"`)와 칸별 `aria-label` "3행 2열 파랑 사각 · 내 영역|영역 밖". 선택 후 **바뀐 칸만** 갱신(같은 값 재기록 금지). 읽기 전용 표시이므로 칸은 초점을 받지 않습니다.
- `role="status"` 한 곳(`#status`)만 `aria-live="polite"`: 선택 결과("파랑으로 번졌어요. 영역 9칸 · 남은 횟수 6"), 같은 색 안내, 승패. 이벤트가 있을 때만 갱신.
- 3px `focus-visible`(잉크 + 흰 외곽선 이중선으로 색 버튼 위에서도 보이게). 키보드로 모든 기능 접근 가능. 초점 순서: 홈 → (준비: 시작, 단계 선택) → 색 버튼 → 조작 줄 → 우측 패널.
- 모달은 열릴 때 첫 버튼에 초점, Tab 순환, 외부 초점 유입 시 모달로 복귀, 닫으면 호출 버튼(없으면 `이어서하기`/`게임 재개`)로 복귀.
- 잔여 위험: TalkBack 등의 접근성 클릭이 DOM 초점 없이 `detail 0` click만 보내는 경우 6.1의 초점 가드로 무시될 수 있음(가정 9). 실제 보조기기는 미검증.

## 12. 소리·에셋 계획

- **직접 제작·합성만**: CSS/인라인 DOM 도형, `AudioContext` 합성음. 이미지·폰트·외부 자산 0, CDN 0, CSP 완화 금지. 구현 보고에 "출처: 직접 제작, 외부 라이선스 없음"을 기록합니다.
- 소리(기본 꺼짐, 사용자 제스처 후 `AudioContext` 생성/재개): 색 선택음(색마다 다른 음, 펜타토닉 4음, 0.12초 사인 + 짧은 감쇠), 흡수가 있으면 짧은 보조음, 완료 아르페지오 4음, 실패 하강 2음, 같은 색 재선택·무시 입력은 소리 없음. 음량 상한 약 0.08. 정지·숨김·결과 전환 시 진행 중인 소리를 즉시 정지. 미지원/예외는 무음으로 정상 플레이.

## 14. 가정/결정 필요 (PM 검토)

원안과 충돌하면 원안 우선, 이유 기록. 이번 설계에서 원안의 수치와 충돌하는 항목은 없습니다.

1. **해금**: 원안에 구체 규칙이 없어 1단계만 열고 단계를 완료하면 다음 단계(최대 15)가 열리는 선형 해금으로 정했습니다(17번과 동일). 입문 5판을 건너뛰고 기본을 바로 하고 싶은 사용자를 위한 별도 해금은 없습니다. 결정 필요: 선형 유지 vs 6단계(기본) 즉시 개방.
2. **패배 기록**: 원안은 "클리어 횟수와 사용 횟수"만 기록하므로 패배는 저장하지 않습니다(쓰기 최소화). 총 도전 수·실패 수 통계는 만들지 않습니다.
3. **누적 총점 없음**: 원안에 없음. 단계별 최고만 있습니다.
4. **칸 클릭 비지원**: 원안 조작은 하단 색 버튼·숫자키입니다. 원작처럼 보드 칸을 눌러 그 색을 고르는 기능은 만들지 않습니다(칸이 조작 대상이 아니므로 모바일 44px 칸 요건·스크롤 문제가 없어짐).
5. **같은 색 재선택 안내와 소리**: 원안은 횟수 불변만 규정했습니다. 안내 문구만 표시하고 소리는 내지 않습니다.
6. **사라진 색 선택**: 이미 판에서 모두 흡수된 색을 선택해도 "유효한 다른 색 선택"이므로 1회로 셉니다. 색 버튼을 비활성화하거나 경고하지 않습니다(원안 해석 그대로). 필요하면 후속으로 "판에 없는 색" 표시를 추가할 수 있습니다.
7. **읽기 예외 시 쓰기 중단**: 읽지 못한 기존 기록을 덮어쓸 위험이 있어 메모리 모드에서는 쓰기를 시도하지 않습니다(17/18 구현은 읽기 실패 후에도 쓰기를 시도). 반대로 손상 JSON(읽기는 성공)은 복구 후 다음 쓰기에서 손상본을 대체합니다. 결정 필요 여부: 낮음.
8. **`bestUsed` 하한**: 저장 검증에서 `bestUsed >= pathLength`를 요구합니다. 이는 솔버 경로가 최소임을 전제하며(전수 BFS로 15개 모두 확인) UI에 "최적"이라 쓰지는 않습니다. 맵을 바꿀 때 하한이 틀어질 위험이 싫으면 `>= 1`로 완화.
9. **접근성 클릭**: `detail 0` click에 초점 가드를 두므로 초점 없이 click만 보내는 보조기기 경로는 미검증 위험입니다(실물 미검증으로 보고).
10. **번짐 연출 길이**: "200ms"를 120ms 전환 + 최대 80ms 지연(총 최대 200ms)으로 해석했습니다. 입력 잠금 없음("논리 판정과 무관").
11. **정지 중 보드 가림 없음**: 타이머·압박이 없는 퍼즐이라 정지 화면에서 보드를 가리지 않고 색 버튼만 비활성화합니다. 정지 패널은 보드 위가 아니라 보드 위쪽 영역에 표시합니다.
12. **테마 이름**: 원안은 "팔레트 테마"만 요구. `paint`(기본, 색약 친화 팔레트)와 `pastel` 두 가지, 둘 다 문양 포함. 원하는 이름·개수가 있으면 변경.
13. **기본 선택 단계**: 준비 화면의 초기 선택은 1단계(17번과 동일). 가장 높은 해금 단계로 시작하는 편의는 넣지 않았습니다.
14. **난이도 곡선**: 경로 길이 4~13의 램프는 설계자가 정한 수치입니다(원안은 "경로 길이+3"만 규정). 15단계 길이 13은 이 크기 4색 무작위판에서 드문 편입니다. 체감 난이도·1~3분 목표는 사람 플레이 전까지 미검증입니다.
15. **홈 카탈로그**: 카드 제목 `물감 번지기`, 장르 퍼즐, 시간 `1~3분`, 경로·ID는 계약 그대로. 카탈로그 통합은 INTEGRATE 담당(이 문서 범위 밖).
