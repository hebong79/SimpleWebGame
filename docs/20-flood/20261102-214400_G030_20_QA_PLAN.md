## 1. 독립 oracle (제품 코드 import 금지, 설계서 규칙만으로 새로 작성)

`oracle.mjs`는 제품 상수·함수에 의존하지 않고, 15개 맵 데이터만 **설계서 3.1 표에서 별도로 옮겨 적은 입력**으로 사용합니다(제품 `STAGES`와 동일한지는 마지막에 대조 단언으로 확인). 비교 대상 제품 API는 인수 문서의 exports.

### 1.1 flood fill 흡수

- 격자 배열과 좌표 루프로 큐/스택 탐색을 직접 구현. 이웃은 `(r±1,c)`, `(r,c±1)`만, 인덱스 ±1 줄넘김 금지.
- 시작 영역 = 0번 칸에서 같은 색 4방향 연결 성분. 색 선택 `c`: 영역 전체를 `c`로 간주하고, 영역에서 시작해 원래 색이 `c`인 칸을 반복 흡수.
- **고정 벡터(손계산 가능)**:
  - V1 `size3,colors3, cells=[0,1,1, 2,0,1, 2,2,0]`: 시작 `{0}`(대각선 `(1,1)`=0은 연결 아님). 선택 1 → `{0,1,2,5}`(2겹 연쇄), 다시 선택 1 → 같은 색(횟수 불변), 선택 0 → `{0,1,2,4,5,8}`, 선택 2 → 전체. 최소 3수. 사용 횟수 1,1,2,3.
  - V2 `size3,colors4, cells=[0,1,1, 2,0,1, 2,2,3]`: 시작 `{0}`. 선택 3 → 영역 `{0}` 그대로이지만 횟수 1(영역이 안 커져도 유효). 선택 3 다시 → 무료. 이어 1 → `{0,1,2,5}`, 0 → `{0,1,2,4,5}`, 2 → `{0..7}`, 3 → 전체. 이 순서는 5수, 솔버 최소는 4수(`1,0,2,3`).
- 무작위 속성 시험(독립 PRNG 시드 고정, 새 시드 사용): 3~8 크기 무작위 격자 2,000개와 임의의 선택 열(같은 색 포함)로 제품 `pickColor`와 oracle의 영역·`used`·`currentColor`·완료 여부 비교. 단조성(영역은 줄지 않음), 영역이 항상 0번을 포함하고 연결, 표시 색 계산(영역=currentColor, 그 외=원래 색) 단언.

### 1.2 제한 횟수와 마지막 수 판정 순서

- 설정 가능한 `limit`(단위 시험용 작은 판, V2의 5수 순서 `3,3,1,0,2,3`을 `limit=5`(6번째 입력이 아니라 5번째 유효 선택에서 완성 → 승리, 점수 0)와 `limit=4`(4번째 유효 선택 직후 영역 8칸, 미완성 → 패배)로 재생)으로: ① 마지막 허용 수에서 완성 → 승리(점수 0, remaining 0). ② 마지막 수에서 미완성 → 패배. ③ 허용 수 이전에 완성 → 남은 수만큼 점수. ④ 같은 색 재선택은 마지막 수 직전/직후에도 무효이고 패배를 유발하지 않음(`used==limit-1`에서 같은 색을 눌러도 `used` 불변·phase `playing`). ⑤ 결과 후 `pick` 무시. ⑥ `used`는 `limit`을 넘지 않음.
- `limit==pathLength+3`, 점수 `(limit-used)*100`(0..300), 경로 길이로 끝내면 정확히 300.

### 1.3 맵과 solver 검증

독립 구현 두 가지로 각 맵을 검사:
1. 영역 비트마스크 BFS(또는 BigInt/배열 어느 쪽이든 제품 솔버와 다른 구조)로 최소 길이를 구함.
2. 다른 알고리즘(깊이 제한 DFS+전치표, 가지치기 `남은 색 종류 수 <= 남은 횟수`)로 `길이-1` 실패/`길이` 성공 교차 확인.

단언: ① 15개 `size/colors`(1~5: 6/3, 6~15: 8/4). ② 각 맵의 모든 색 존재, 시작 영역이 전체가 아님(단색·이미 완성 금지), 시작 영역 ≤4칸. ③ 제품 `path`를 oracle flood로 재생하면 `pathLength`번째에서 **처음** 완성되고 연속 같은 색이 없음. ④ oracle 최소 길이 == 제품 `pathLength`(제품 값이 최소보다 길면 FAIL 후보가 아니라 **보고 사항**: 설계서 3.3은 최소임을 전제로 저장 하한을 쓰므로 PM에 알림. 최소보다 짧은 `pathLength`는 FAIL). ⑤ `limit==pathLength+3`. ⑥ 맵 중복 없음: 색 첫 등장 순서 재번호 정규화 후 중복, 전치 후 정규화 중복 모두 없음. ⑦ 제품 `STAGES.cells`가 설계서 표와 문자열 동일(다르면 PM에 차이 보고, 설계서 정본 기준). ⑧ 15개 `path`로 UI 완주 가능성은 4절에서.
- 문자열 표기 확인: 설계서 표의 `경로`는 숫자키(색+1) 기준이므로 oracle은 변환 후 재생.

### 1.4 저장 스키마 oracle

키 `simplegames.paint-spread.v1`, `version:1`, `settings{theme:'paint'|'pastel', muted:boolean}`, `records{completed, unlocked, stages[15]{clearCount, bestUsed, bestScore}}`, CAP 1,000,000. 독립 검증 함수(설계서 5.3)를 작성해 제품 `recoverRecord`와 비교:

- 기본값, 잘못된 JSON, primitive(`1`,`"x"`,`true`,`null`), 배열, `version` 0/2/문자열, 누락 필드.
- 단계 배열 길이 14/16, 항목 null/배열/문자열, `clearCount` NaN/Infinity/음수/소수/문자열/2^53/CAP+1, `clearCount==0`인데 `bestUsed` 비null(또는 반대), `bestUsed`가 `pathLength` 미만/`limit` 초과/소수/문자열, `bestScore !== (limit-bestUsed)*100`.
- 단계별 **독립 복구**: 한 단계만 불량이면 나머지 14개 보존. 불량 theme만(유효 기록 보존), 불량 muted만(유효 기록·theme 보존). 저장된 `completed`/`unlocked`가 파생값과 다르면 파생값 사용(경고).
- 읽기 시 쓰기 0(`Storage.prototype.setItem` 호출 카운트).
- 정산: `settleRecord`의 `rejected`(범위 밖 단계, 잘못된 used/score), 정상(+1, min/max, 해금 `max(unlocked,min(15,id+1))`), 새 객체 반환·입력 불변, 같은 `used`에서 `tie`, 더 적은 `used`에서 `new-best`, 더 많으면 `not-best`(bestUsed 유지·clearCount만 +1).
- 포화: `clearCount==CAP` 또는 `completed==CAP`일 때 **참조 동일/모든 필드 불변**(`bestUsed`·`bestScore`·`unlocked` 포함 부분 증가 없음). `completed==CAP-1`에서 한 번 더 → 정확히 CAP, 다음은 불변.
- 예외 주입: `getItem` throw, `localStorage` getter throw, `setItem` throw(QuotaExceeded 모방) → 메모리 모드/지속 경고. 읽기 예외 후 **쓰기 시도 0**(설계서 5.5/가정 7). `setItem` 성공 복귀 후 경고 해제. 다른 키(`simplegames.*`) 값 보존.

## 3. 브라우저 시나리오(AC 번호는 설계서 15절)

### A. 기본 흐름
1. 직접 URL 로드 → 준비 화면(AC 17): 단계 15개 버튼(2~15 잠김 표시와 aria-label), 시작 전 색 버튼 비활성, 시작 전 색 입력/숫자키 무시, 보드는 1단계 시작판 미리보기.
2. `게임 시작` → playing. 색 버튼을 실제 100ms 누름으로 눌러 1단계(경로 `3,1,2,3` 숫자키)를 UI 입력만으로 완주 → 점수 300, 사용 4/7, 정산 쓰기 정확히 1회, 2단계 해금(AC 11, 20, 21).
3. 결과 화면: `다음 단계`(→2단계 새 round), `다시 도전`(같은 맵 used 0), `단계 선택`(→ ready), `홈으로`(링크). 15단계 결과는 `다음 단계` 숨김과 완료 문구.
4. **15단계 전부를 trusted UI 입력만으로 완주**하고 각 단계의 사용 횟수·점수·정산·해금과 최종 `completed 15`, `unlocked 15`, 모든 bestScore 300을 저장 JSON과 대조(스냅샷은 관찰용, 상태 setter 없음). 경로는 oracle이 구한 최소 경로 사용(제품 `path` 재사용 금지).

### B. 규칙(AC 02~06)
- 실제 UI에서: 같은 색 버튼 연타(더블탭 포함) → 횟수 불변, 안내 문구만, 쓰기 0. 영역이 커지지 않는 색(예: 영역 이웃에 없는 색) 선택 → 횟수 +1(스냅샷 `lastEvent.absorbed==0`, `counted`). 판에서 사라진 색 선택 → +1.
- 마지막 허용 수 시나리오: 한 단계에서 의도적으로 낭비 수를 두어 `used==limit-1` 상태를 만든 뒤 ① 같은 색을 눌러도 phase `playing` 유지 ② 영역이 전체가 되는 다른 색을 눌러 승리(점수 0, 결과 승리, 정산 1회, 해금) ③ 별도 시도에서 미완성인 수로 마지막 수를 쓰면 패배(쓰기 0).
- 패배 후 `다시 도전` = 같은 맵·`used 0`·새 round, `used==limit`에서 추가 입력 무시.

### C. 입력(AC 12~16)
- 숫자 `1`~`4` 선택, 3색 단계의 `4` 무시(`defaultPrevented` 없음, 키 소비 없음), `Ctrl/Alt/Meta` 조합 무시, `e.repeat` 무시, 눌린 상태로 두 번째 keydown 무시, keyup 후 재입력 허용. 입력 필드/외부 요소가 초점일 때 숫자키가 게임을 건드리지 않음(테스트용으로 페이지에 임시 input을 주입하는 것은 제품 변경이 아니라 관찰 하네스 범위로 표시).
- ←/→로 색 버튼 초점 이동, 가장자리 멈춤, Home/End. Enter/Space 활성화, 자동 반복(`repeat`) 무시, 승리 직후 새 주 버튼으로 초점이 이동해도 계속 누른 Enter가 `다음 단계`를 연속 활성화하지 않음.
- 포인터: 같은 버튼 down/up 이동 ≤8px 정상, 8px 초과(드래그)·다른 버튼 위에서 놓기·보드 밖에서 놓기·`scroll` 발생·`pointercancel`·`lostpointercapture`·두 번째 포인터(보드 밖 포함)로 취소, 취소 직후 합성 click 억제. 누름 시간 80/100/300ms가 모두 정상 처리됨을 확인(설계서는 80ms 이상 trusted 누름이 정상 동작해야 한다고 요구).
- 터치 두 손가락(Chromium mobile CDP)과 마우스/합성 포인터(WebKit/PC)는 결과에 방식을 표기.

### D. 정지·모달(AC 18~19)
- 수동정지(버튼/Esc) → `이어서하기`, 보호정지(blur, `visibilitychange` hidden, `pagehide` dispatch) → `게임 재개`, 모달 정지 → `게임 재개`. 정지 중 색 버튼·숫자키·합성 click 무시, 상태(보드·used·region) 불변, 재개는 명시적 버튼만, 재개 후 초점이 색 버튼.
- 모달(도움말, 테마, 진행 중 홈 확인, 진행 중 처음부터 확인): 열기 전 먼저 정지, 취소/닫기는 정지 복귀, Esc는 닫기만(확인 동작 미실행), Tab/Shift+Tab 양 경계 순환, 외부 초점 강제 유입 시 모달 복귀, 낮은 viewport 높이에서 모달 내부 스크롤, 닫은 뒤 초점 복귀.
- 모달 열린 중 blur/hidden → 모달 유지, 닫은 뒤 보호정지(`pendingProtection` 소비 후 false). 준비/결과의 모달은 phase 불변.
- 진행 중 홈 링크 클릭(확인 → 취소/확정), 준비/결과 홈 직접 이동. 포기는 쓰기 0.
- 이 게임은 논리 잠금·RAF가 없으므로 "잠금 동결"·"delta>250ms 보호정지"는 **해당 없음**으로 표시하고, 대신 상시 RAF/타이머가 돌지 않음(MutationObserver 0, 대기 30초 후에도 DOM 변화 0)을 확인.

### E. 시각 연출(AC 27~28)
- 영역 클래스(테두리 변)가 선택마다 올바른 변에만 붙는지를 oracle의 노출 변 계산과 DOM 클래스로 대조(진행 중 3개 단계, 완성 시 보드 둘레).
- 번짐: 선택 직후 계산 스타일의 `transition-duration`≤120ms, `transition-delay`≤80ms, 총 ≤200ms. 번짐 도중(50ms) 다음 입력이 처리되는지(잠금 없음), 판정·스냅샷은 번짐 종료를 기다리지 않음. `prefers-reduced-motion: reduce` 에뮬레이션에서 전환 0, 판정 동일.
- 캡처 이미지를 직접 열어 확인(시각 항목): 준비/플레이(영역 테두리 포함)/정지/결과 승리·패배/모달, PC 1366과 mobile 320, 두 테마. 확인 사항: 겹침·가로 잘림 없음, 4색+문양 구별, 테두리 가시성, 3px 초점 링, 색약 눈검사(채도 제거/적록 시뮬레이션 캡처 포함, 시뮬레이션 방법을 기록). 실물 색 재현은 미검증.

### F. 저장·설정 UI(AC 20~26, 34)
- 쓰기 카운트(`Storage.prototype.setItem` 후킹 + `__g030Snapshot().storage.writeCount` 교차): 읽기·준비·단계 선택·시작·같은 색·정지·모달 취소·테마 모달 취소·처음부터·포기·패배·홈에서 0, 승리 정산 최초 1회, 테마 적용(값이 바뀔 때만)·소리 토글만 쓰기.
- 정산 1회: 승리 직후 정지/재개/모달/창 blur·복귀/결과 화면에서 `다시 도전` 전까지 쓰기 1회 유지, 재시작 후 같은 단계를 다시 승리하면 clearCount +1과 새 정산 1회. reload 후 기록·설정 유지, 진행 중이던 판은 복원되지 않음.
- 저장 오염 주입(`addInitScript`로 로드 전 `localStorage` 설정): 1.4 목록 중 UI 대표 케이스(손상 JSON, 일부 단계 불량, 불량 theme, version 불일치, 포화 근방)에서 복구와 경고 표시 확인. 차단/예외 주입은 init script 모의임을 표기.
- 저장 실패 문구(AC 25): `setItem` throw 상태에서 승리 → 결과 줄에 "이번 페이지에서만 유지돼요"류가 나오고 "저장했어요" 문구가 없으며 지속 경고가 표시됨. 이후 `setItem`이 복구되고 다음 쓰기(예: 소리 토글)가 성공하면 경고 해제, 이후 승리의 결과 줄은 저장 성공 문구. 읽기 예외 시작 상태에서는 쓰기 시도 0이고 경고 지속.
- 포화(AC 26): `clearCount=1,000,000`(해당 단계) 또는 `completed=1,000,000`인 기록으로 시작 → 승리 시 어떤 필드도 증가하지 않고 결과에 "기록 한도…" 안내, "저장했어요"/"새 최고" 문구 없음.

### G. 레이아웃·접근성(AC 30~31)
- PC 1366과 320px: `document.documentElement.scrollWidth <= clientWidth`, 보이는 모든 `button`과 `a`(**`a#home` 포함, 결과의 홈 링크 포함**)의 `getBoundingClientRect` ≥ 44×44, 보드 전체가 스크롤 없이 보임, 3색 단계에서 4번 버튼 숨김(탭 순서 제외), 색 버튼 폭 ≥ 44px.
- 상태 기호: 색 버튼과 칸마다 문양(`data-color`)·숫자·`aria-label`, 현재 색 `aria-pressed`, 테마 변경 후 동일. `role="status"` 한 곳만 live.
- `focus-visible` 3px 이상 두께(계산 스타일), 키보드만으로 시작~결과 완주 가능.

### H. 소리(AC 32)
- 기본 muted(저장 기본값), 토글 저장. `AudioContext` 스텁/미지원 시 예외 없이 플레이. 정지·hidden·결과 전환에서 `stop` 호출. 실제 청취는 **미검증**.
