## 공통 실행 계약

- 시작 전 목표와 첫 입력을 안내하고 시작→첫 유효 입력→목표/승패→재시작/재대결→홈 복귀를 제공합니다. 퍼즐에는 실행 취소와 재시작, 대전에는 재대결을 제공합니다.
- 포인터·터치와 키보드로 동일한 실제 규칙을 조작합니다. 버튼 최소 44×44 CSS px, 촘촘한 보드는 320px 가로 넘침 없이 표시하며 방향 포커스+확정 입력을 제공합니다. 게임 밖 포커스에서는 방향키를 가로채지 않습니다. 키 자동반복/길게 누름과 포인터 중복 활성화를 막습니다.
- 색과 기호/문양/테두리를 함께 사용합니다. 소리 없이도 상태를 판단할 수 있어야 합니다. 비필수 효과는 줄일 수 있습니다. 탭 이탈은 진행과 예약 입력을 멈춥니다.
- 저장은 게임별 독립 버전 키입니다. 기록·외형을 판 상태와 분리하고 빈 저장·손상·차단에서도 기본값과 플레이를 보장합니다. 새 판/취소/힌트로 완료나 해금을 중복 가산하지 않습니다.
- PM 공통 `public/games/vol4/shared.mjs/css`는 기존 vol3 API를 기반으로 합니다. `window.__vol4`, `simplegames.vol4.<id>.v1`, `ctx.newRound(callback)`은 확인 후 callback→reset/start이며 취소는 현재 판을 보존합니다. 공유 UI 및 홈 파일 수정은 PM만 합니다.
- 외형 선택이 이동·판정·속도·카드 효과·진영/사범/로봇 식별을 바꾸면 실패입니다. 원안 해금 기준은 아래 표와 같으며 공유 UI의 기본 2/5승으로 대체하지 않습니다. 대전의 '판 완료'는 승리만 세는 것과 구분합니다.

## 통합 및 수용 단계

1. builder가 해당 소스·자체 규칙검증·풀이증인/해수와 실제 출력물을 인계합니다. PM이 실제 파일을 읽습니다.
2. PM은 홈에 정확히20카드를 등록하고 기존89기록/60플레이와 합산109기록/80플레이/29준비를 확인합니다. 이 수는 기존 레코드가 그대로인 조건입니다.
3. 운영과 별도 새 후보에 typecheck/build/자동 규칙검증을 수행합니다. 독립 QA는 builder 보고를 복사하지 않고 핵심 음성 사례와 320px·키보드·저장차단·턴숨김을 직접 확인합니다.
4. 초기 HTTP smoke부터 PC Chromium/모바일 Chromium/모바일 WebKit에서 실제 시계80ms trusted 누름과 CSP를 검사합니다. 가상시계/순간click을 실제입력 대신 세지 않습니다. 시작·첫입력·정지/재개·홈을 확인하고 공통UI수정은 기존게임회귀로 검증합니다.
5. 승인된 Git/단일앱 운영반영은 PM이 G020을 따릅니다. PM2 script/PID/LISTEN, HTTP실제바이트, 사용자주소15010에서 새카드클릭→시작→입력→정지→홈이 확인되어야 운영완료입니다. CLI exit0/PM2online/후보PASS만으로 전체완료를 선언하지 않습니다.
6. PM은 KST 실제시각의 작업일지·HANDOFF·중복없는 게시판요약/readback 링크를 남깁니다. planner의 이 문서는 해당 최종기록을 대신하지 않습니다.
