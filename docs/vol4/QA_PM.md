## 실제 브라우저 입력

Chromium PC와 모바일 WebKit320px 각각5게임의 첫 문제를 실제 시계80ms trusted 입력으로 끝까지 완주했습니다. 가상 시계를 사용하지 않았습니다. 시작, 유효 포인터/키보드 입력, 취소, 정지 시 모델/경과시간 동결, 도움말 native Enter, 문제 변경 확인/취소/reset, 성공, 독립 저장 완료ID, 재시작을 검사했습니다. Mosaic는 드래그→첫 칸 재방문이 토글되지 않는 점과 한 제스처를 한 번의 undo로 복구하는 점을 검사했습니다. 69는 실제 초점 칸의 WASD, 개별 위반 `!`, SVG 터치 영역44px도 명시 검사했습니다.

공유 셸은 독립 API fixture로 사용자 정의 `themeProgress`를 로드 시 적용하는지 0/3/7/8/음수 경계에서 검사했습니다. 총 wins999를 주어도 custom progress0이면 잠긴 외형이 기본으로 복구됩니다. 손상 JSON/저장 거부에서도 시작·완료·메모리 최고기록을 유지하며 저장 경고가 보입니다. 제품의 다른 저장키를 합치거나 운영 브라우저 프로필을 사용하지 않았습니다.

모든 대상에서320px 문서 가로 넘침0, 보드 버튼44px, 브라우저 런타임·CSP 오류0을 확인했습니다. WebKit은 캡처하지 않았으며 오류 필터를 두지 않았습니다. Chromium 캡처 `69-pearl-320-chromium.png`, `70-mosaic-320-chromium.png`를 실제로 열어 위반 표식·범위 하이라이트·내부 스크롤 배치를 눈으로 확인했습니다.
