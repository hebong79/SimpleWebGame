# G026-14 — 별과 달 3목 / buildable design v1.0

Authority: G026_PM_CONTRACT.md and read-only original14. Local two humans on ONE device, no AI/network/account/ranking. Distinct fixed players `X` (별) and `O` (달), shape+letter+label.

## Engine and turns
- 3x3 row-major board indices0..8, values null|X|O. Canonical8 winning lines rows012/345/678, columns036/147/258, diagonals048/246.
- First completed-session game starterX. Successful placing into an empty cell is exactly one move; invalid primitive/noninteger/out of range/occupied/input locked/notplaying is same state no-op without changing turn/winner/round/stats/audio. Symbols/objects must not be coerced. No animation lock needed to prevent duplicate turn; transition synchronous.
- Each placement: set mark -> increment moves -> evaluate ALL winning lines -> if mover wins set result/winner/winningLines and settle once; ELSE if moves9 draw; ELSE swap current turn. Ninth-move win always beats draw. On any result all further board input blocked. Two winning lines on final move both highlighted, one result only.
- Fixed player identities remain X/star and O/moon. On `Next round` AFTER completed win/draw, next starter is opposite of prior starter, even if prior starterO and even ifX won. Alternation is NOT based on winner. Abandon/restart active round preserves that round's starter; it is not a completed round and increments no counts. Ready changes no stats. Reload starts new session with starterX and empty board, not automatic gameplay.
- Engine round ID/token changes on every fresh round. Repeated next/retry clicks and held Enter must not skip starters or start multiple rounds; choose UI disabled/release-gating so one user activation -> one round. No RNG required; invalid input must never access randomness.

## State/UI behavior
- Ready -> Start playing -> pause -> result. Timer is optional display? RESOLVED: no timer/bonus; this game has no time metric. Status names current player `별 X의 차례` / `달 O의 차례`; show both players in score strip, sessionX wins / draws / sessionO wins.
- Roving tabindex on9 native button cells. Arrow keys within focused board move selection one row/column, clamp at edges (no wrap); Enter/Space place. Occupied cells remain navigable/announced, activating does not change turn. After valid place retain selected cell; next user deliberately selects next. No global keys when focus is toolbar/dialog. Ignore modifiers and event.repeat/held duplicate; plain Tab normal.
- Result uses winner label or `무승부`, all winning lines shape/border, session and lifetime records. Next round primary and home, no unnecessary confirmation on completed round. Restart/home during active game confirm abandon, cancel keeps board/starter/stats and paused reason. Help/style pauses and requires explicit resume; blur protection semantics shared contract.
- Visual style `paper` default and `night` both available. Apply changes board/mark appearance only; preview/cancel restores appearance without board/turn mutation. GeometricX/O and text remain discernible. Two original mark SVGs or sprite per style, no reference art, no costume system. Buttons >=72px at320px board, toolbar >=44px.

## Session vs persistent records — explicit resolution of brief ambiguity
- Original specifically says session wins/draw/loss but common paragraph says local-record saving. Keep SESSION score only in memory (reload -> all0), and separately labeled LIFETIME completed round totals in localStorage; do not restore lifetime into session. Session never reset by next/restart; only reload/new page resets. No hidden session reset feature needed.
- Persist `{version:1, settings:{theme:'paper'|'night',muted:boolean}, lifetime:{xWins,oWins,draws}}`. Nonnegative safe integers, total<=1000000; use safe/BigInt sum validation. At total cap do not increment any lifetime counter, but gameplay and session proceed; show record cap warning. Session also total cap1000000, stop increment at cap (no overflowing counters). No best-score concept or fictitious ratings.
- At actual round completion one synchronous transaction increments correct session/lifetime counter if under cap and writes once. Abandon/start/restart/ready/modal/pause do not write totals. A write failure keeps updated memory and persistent warning; reload may lose unsaved result, never claim saved.
- Recovery unit: invalid lifetime resets all THREE mutually related lifetime counts to0, with warning; valid settings preserved. Each invalid settings field resets only its own default. Invalid JSON/version defaults own record in memory and warns, no automatic writes/deletion, other keys preserved. localStorage getter/getItem/setItem failures independently covered.
- Sound muted default; place/win/draw distinct synthesized cues, AudioContext unavailable/throws -> silent functional play. All events clear visual status.
