# SimpleGames 운영 완료 기준과 작업 순서

## 목적과 적용 범위

게임 소스가 생긴 것과 마스터가 실제로 플레이할 수 있는 상태를 구분합니다. 이 프로젝트에서 일반적인 **게임 제작/추가 작업의 최종 목표는 기존 실사용 `http://192.168.0.195:3116/`에서 새 게임을 바로 선택·실행하는 것**입니다. 설계만/개발 지시만 요청한 경우에는 그 단계만 수행하고 운영 미반영을 명확히 표시합니다.

이 문서는 무검증 자동 배포나 상주 감시 서비스가 아닙니다. PM이 작업 중 수행해야 하는 인수·배포 절차입니다. 실제 운영 변경은 현재 요청의 승인 범위와 AGENTS 안전 규칙을 따릅니다. 운영 반영 승인이 불명확하면 착수 때 범위를 한 번 확정하고, 완료 때 뒤늦게 빠뜨리지 않습니다. 다른 서비스/새 포트/방화벽/ACL/비용/외부 배포/원격 push는 별도 범위입니다.

## 역할과 상태

- 구현자: 배정된 게임 소스·단위시험·인수 문서. 공통 홈/서버를 임의 변경하지 않습니다.
- 독립 QA: 소스 동결 후 배정된 검사·결함·증거. 자기 구현의 단독 최종 승인자가 되지 않습니다.
- **PM 대현자:** 워커 인수 → 홈 등록 → 빌드 → 통합 검사 → 승인된 Git 작업 → 운영 전환 → 실제 사용자 주소 실행 확인 → 게시까지 단독 책임집니다.
- 워커를 배정할 때 PM 후속 작업과 의존성을 같은 작업 목록에 등록합니다. ACK/자체 시험 PASS는 전체 게임 완료가 아닙니다. native 워커에 자동 완료 알림 연동이 없다면 PM이 실제 결과를 조회해 인수해야 하며, 상주 감시가 설치됐다고 주장하지 않습니다.
- 상태: 설계/배정 완료 → 구현 인수 → 통합 검증 완료 → 운영 전환 → **운영 실행 검증 완료**. 앞 단계 완료를 마지막 단계로 표현하지 않습니다.

## 필수 단계와 중단 기준

| 단계 | 담당 | 반드시 남길 확인 | 실패하면 |
|---|---|---|---|
| 1. 착수 | PM | 현재 실사용 URL·PM2 앱/실행 경로·카드 수·Git 상태·운영 반영 승인 범위 | 미정 범위를 먼저 확정 |
| 2. 배정/인수 | PM·구현자 | 실제 구현 파일/완료 응답/단위 결과·변경 파일·인수 문서 | 구현 인수 미완료 유지 |
| 3. 홈 통합 | PM | 고유 ID·title·available·href·아트, 기존 ID/즐겨찾기/저장키 보존 | 카드만 추가하고 완료하지 않기 |
| 4. 새 후보 빌드 | PM | 사용 중이지 않은 새 디렉터리·타입/빌드 성공·파일 SHA256 | 옛 dist/빌드로 대체하지 않기 |
| 5. 조기 실제HTTP smoke | PM·QA | 새 게임 URL/모듈200·화면·시작/정지/재개·80ms trusted 누름·CSP/console/자산 오류0 | 전체 심층 리뷰 전에 결함 수정 |
| 6. 수용 게이트 | 독립 QA·PM | 엔진/저장 단위·홈/기존 게임 회귀·PC/모바일 Chromium/WebKit·실제 시계와 가상시계 구분 | 원본 FAIL 보존·수정 후 재검사 |
| 7. Git(승인된 경우) | PM | 관련 파일만 stage·staged whitespace/비밀 검사·커밋·정상 병합/tree | 무관한 변경/강제 push/reset 금지 |
| 8. 단일 운영 전환 | PM | 직전 빌드/설정 보존·대상 게임 앱 하나만 검증 빌드로 전환 | 다른 앱/방화벽/ACL 변경 금지 |
| 9. 실행 경로 확인 | PM | PM2 실제 pm_exec_path·PID·LISTEN 포트가 새 빌드와 일치 | **다음 운영 브라우저 검사를 시작하지 않기** |
| 10. 실제 운영 수용 | PM·QA | 마스터가 쓰는3116에서 새 카드 클릭→시작→입력→정지→재개→홈, 실제 응답과 빌드 SHA256 일치 | 운영 반영 미완료/필요시 승인 범위 롤백 |
| 11. 마감 | PM | HANDOFF/상태·작업일지·보드 실제 본문/첨부·운영 화면 | 게시/미반영 상태를 분리 보고 |

## 빠뜨리기 쉬운 기술 항목

1. **소스 수정/커밋/병합만으로 현재 PM2 서버가 갱신되지 않습니다.** 현재 서버는 빌드 산출물을 제공하며 소스 자동 동기화나 hot reload가 설정된 서비스가 아닙니다.
2. 후보 빌드에서 카드가 보여도3116 반영 완료가 아닙니다. 기존 개발3102나 다른 임시 포트를 실사용 주소 대신 검증하지 않습니다.
3. 이 환경에서는 ecosystem의 script 경로를 바꾸고 restart가 exit0이어도 기존 pm_exec_path가 남는 현상을 실제 확인했습니다. **CLI 성공이 아니라 재조회 결과**로 판단합니다. 같은 경로 재시작은 restart를 쓰되, 경로 전환이 실패하면 승인된 동일 게임 앱만 새 설정으로 재등록하고 다시 확인합니다. 항상 delete/start하는 무조건 규칙이 아닙니다.
4. WebKit native select/UA 스타일과 엄격 CSP 충돌은 외부 CSS·접근성 버튼으로 해결하며 unsafe-inline·오류 필터로 숨기지 않습니다.
5. RAF마다 버튼 또는 그 자식의 동일 textContent를 재할당하지 않습니다. 값이 바뀔 때만 갱신합니다. 새 게임의 첫 실제HTTP 검사부터 **비동결 시계·약80ms trusted 클릭·Enter/Space 반복·초점/모달·좁은 화면**을 검사합니다. 순간 클릭/동결 시계만으로 실제 누름을 대신하지 않습니다.
6. 기존 QA 출력은 덮지 않습니다. 환경변수와 모든 고정 출력경로를 child 실행 전에 새 경로로 지정합니다.
7. 임의의 총 게임 수를 영구 상수로 쓰지 않습니다. 작업 시작의 기존 ID와 승인된 신규 목록에서 기대 수/링크를 확정합니다. 현재 기준은35/6/29이며 다음 게임이 추가되면 기대값을 함께 갱신합니다.

## 완료 보고 허용 기준

아래가 모두 충족돼야 **“게임 제작 및 운영 반영 완료”**라고 말합니다.

- [ ] 구현 결과를 PM이 실제 인수했습니다.
- [ ] 공통 홈에서 새 게임 카드가 보이고 경로가 정확합니다.
- [ ] 현재 소스의 새 빌드를 검증했고 기존 게임/기록을 보존했습니다.
- [ ] 독립 검토와 실제HTTP·현실적 누름·브라우저 게이트를 통과했습니다.
- [ ] 요청된 커밋/병합을 마쳤습니다. 원격 push 여부는 별도로 표시합니다.
- [ ] 승인된 단일 운영 앱의 실제 실행 경로/PID/LISTEN이 검증된 빌드와 같습니다.
- [ ] **3116에서 사용자가 정상 입력으로 새 게임을 실제 실행할 수 있습니다.**
- [ ] 실제 운영 검증·화면·게시판/첨부 readback과 남은 한계를 남겼습니다.

하나라도 빠지면 “구현 완료, 운영 미반영”처럼 미완료 단계를 명시합니다. 승인이나 환경 문제로 막힌 것을 자동 우회하지 않습니다. 실물 기기/실청취/인간 플레이 시간은 별도 수용이며 미실행을 PASS로 바꾸지 않습니다.
