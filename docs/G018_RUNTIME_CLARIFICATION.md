
## G018 실행기 기술실패의 공식 자동 검토 경로 — 추가 PM 지시

최초 개발턴에서 두 워커는 계약의 '샌드박스실패시중단'을엄격히적용해정상중단했습니다. cody-01에서는기본호출의helper_sandbox_lock_failed 뒤공식자동검토재실행의TEAM/project읽기exit0도실제확인했습니다. 이추가지시는그중단문구를아래처럼명확히대체하며개발범위나보안을확장하지않습니다.

- Windows helper_sandbox_lock_failed/SetNamedSecurityInfoW는기본실행기초기화의기술실패입니다. **기존 on-request + auto_review의 정식 승인 요청을 거쳐 적격 명령을 재실행하는 경로**는허용합니다. 샌드박스기본검사/위험검토를우회하거나강제승인하라는뜻이아닙니다.
- 이미확인된같은기본초기화오류를반복호출하지말고,정식도구가제공하는공식승인검토요청을사용할수있습니다. 실제승인/거부는auto_review가판단합니다. 허용프로젝트/허용경로안문서읽기·신규게임구현·자기시험만대상입니다. 승인없이다른실행기/더약한도구로우회하지마세요.
- **정식 검토에서 거부/추가 인간승인 요구/같은 명령의 검토 후 실패2회/사용량한도/다른 writer 충돌**이면즉시중단하고원문을보고합니다. 전역config/ACL/폴더신뢰/인증/모델/샌드박스종류/networkAccess/운영서버를바꾸지않습니다. 승인요청콜백을임의로응답하지않습니다.
- 필수문서를읽은뒤원래정확한ACK를남기고,원래단독쓰기범위에서실제구현과자기단위시험을이어가세요. 공식재실행성공뒤에는과거첫기본실패만으로작업을다시중단하지않습니다. 원본실패턴/오류는보존합니다.
