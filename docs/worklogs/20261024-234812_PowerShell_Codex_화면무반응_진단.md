# PowerShell Codex 화면 무반응 진단 — 초기화·실행 정책·폴더 신뢰 분리

- 진단 시각: 2026-10-24T23:48:12+09:00
- 요청: PowerShell에서 codex 화면은 나오지만 동작하지 않는 이유 확인
- 결론: 현재 사용자 화면의 단일 원인을 확정한 것은 아닙니다. 정상 실행되는 진단 경로와 독립적인 실패 지점을 실제로 확인했습니다.

## 실제 확인

1. npm 전역 Codex는 현재 **0.164.0**입니다. 이전 조사 당시 0.137.0이던 상태로 추정하지 않고 package.json과 실제 실행 결과를 재확인했습니다.
2. PowerShell 7.6.8의 `codex --version`과 --help는 정상 종료합니다. 이 호스트의 유효 정책은 RemoteSigned입니다. PS1 경로는 C:/Users/hebon/AppData/Roaming/npm/codex.ps1 입니다.
3. 별도 Windows PowerShell 5.1의 기본 `codex`는 codex.ps1 실행 정책 차단으로 실패했습니다. 반면 `codex.cmd --version`은 0.164.0으로 종료 0입니다. 이것은 별도 진입점 차이이며, 화면이 이미 뜬 사용자 증상의 원인으로 단정하지 않습니다.
4. 전역 0.164.0의 `app-server daemon version`은 Codex 로컬 app-server-control.sock 연결에서 **OS error 10050 / 종료 1**입니다. AF_UNIX 드라이버 afunix는 RUNNING이며, TCP 소켓 생성은 정상입니다. PC 전체 인터넷 장애나 드라이버 중지를 원인으로 단정하지 않습니다.
5. PowerShell 7에서 아래 명령을 **별도 진단 PTY**로 실제 실행했습니다. OpenAI Codex 0.164.0 화면과 **Folder access / Trust this folder?** 승인 메뉴까지 도달했습니다. 해당 메뉴에서는 자유 질문 입력 대신 신뢰 여부를 선택해야 합니다.
6. 신뢰를 승인하지 않고 Esc로 진단용 프로세스만 종료했습니다. 추적 ID proc_631228757882, PID 33384, 실제 종료 0입니다. 이는 진단 창에서 초기 화면 표시와 Esc 입력 처리가 동작했음을 증명합니다. 사용자 원래 창의 키보드 동작이나 모델 질의 성공을 증명하지는 않습니다.

## 실제 검증한 진단용 실행 명령

PowerShell 새 탭에서:

```powershell
codex.cmd --no-daemon --no-alt-screen --sandbox read-only
```

- --no-daemon: 문제를 보인 로컬 공유 데몬 경로를 사용하지 않는 임시 진단 실행입니다.
- --no-alt-screen: 화면 모드 문제를 분리하기 위한 옵션입니다.
- --sandbox read-only: 진단 중 모델의 파일 수정 권한을 읽기 전용으로 제한합니다.
- .cmd 진입점: PowerShell 스크립트 실행 정책을 전역 변경하지 않고 검증된 npm 실행 진입점을 사용합니다.

실행 결과에 Folder access / Trust this folder?가 보이면 채팅 입력 창이 아니라 승인 메뉴입니다. 본인이 신뢰하는 프로젝트인지 확인한 경우에만 사용자가 Trust and continue를 선택할 수 있습니다. 원치 않으면 Esc로 종료합니다. 폴더 신뢰는 저장되며 폴더 설정 코드가 자동 실행될 수 있으므로 대현자가 대신 승인하지 않았습니다.

## 검증 경계와 다음 확인

- 사용자에게 실제 터미널 종류와 입력 불능/응답 불능 구분을 문의했으나 응답을 받지 못했습니다. 따라서 정확히 어느 단계에서 멈췄는지는 미확정입니다.
- 현재 진단은 읽기 전용 명령·실행 파일 버전·정책 조회·소켓 점검과 별도 PTY의 초기 UI/종료 검증입니다. 실제 모델 질의는 보내지 않았고 기존 IDE/데스크톱 Codex 세션을 종료하지 않았습니다. 신뢰/권한/인증/전역 정책을 변경하거나 게임 코드를 수정하지 않았습니다.
- 데몬을 사용하지 않는 진단 실행에서도 문자가 전혀 입력되지 않는다면 터미널 포커스/IME/입력 처리 쪽의 별도 확인이 필요합니다. 사용자 멈춤 화면을 확인하기 전에는 복구 완료로 표현하지 않습니다.
- 이번 상태는 진단 경로 확인이며 사용자 화면 정상화는 확인 대기입니다.
