## 2. 레벨 배치와 순수 엔진 계약
- 공통: 벽돌 x=48+col×(69.25+10), 너비69.25, 높이28, col0..7,row0..3. y기준144. 좌우 코트 경계는 공 중심 반지름9의 내부입니다. 패들 중심 기본x360, 위쪽y884, 내부 이동 x60..660.
- stage1 y=144+row×42. stage2 y=144+row×42+abs(col-3.5)×8. stage3 y=144+row×44+(col%2)×16. 항상32개이며 서로 겹치지 않습니다. 마지막 생존 벽돌만 윤곽과 작은 별 표식으로 강조하고 판정은 바꾸지 않습니다.
- DOM 없는 `engine.mjs`에서 `RULES`, `createGame`, `startGame`, `launchBall`, `pauseGame`, `resumeGame`, `step`, `finishGame`를 export합니다. 상태/반환 API를 구현 문서에 정확히 기록하며 QA는 임의의 다른 API를 가정하지 않습니다.
- 상태는 status ready/playing/paused/finished, phase attached/flight, stage/lives/score, paddle, ball, bricks, endReason을 가집니다. `step(state, seconds, input)`은 이벤트 배열을 돌려주고 상태는 일관되게 갱신합니다. ready/paused/finished에서 시간 진행은 no-op입니다. 유한한 양수 dt만 허용합니다.
- 충돌은 연속 충돌시점(swept collision) 또는 충분히 작은 고정 substep+검증된 보정으로 해결하되 긴프레임/고속에서 얇은 벽돌·패들을 통과하지 않아야 합니다. 꼭짓점·동시 접촉은 위치 보정과 다음 루프의 epsilon을 적용해 끼임/다중 득점을 방지합니다. stage 전환이나 목숨 소모 후 그 호출의 남은시간을 새 공/다음 stage에 소비하지 않습니다.
- 패들/공/벽돌의 물리에는 스킨/음소거/렌더 변수를 넣지 않습니다. 무작위 값은 장식별 deterministic 시드만 쓰고 경기 규칙에는 불필요한 RNG를 넣지 않습니다.

## 3. 화면·입력·상태 전이
- **조작형(Operate) 화면**: 큰 코트와 실제 점수/목숨/잔해 수가 우선입니다. 데스크톱 2열, 모바일 1열, 코트 논리 비율3:4를 유지합니다. 320px에서도 문서 가로 overflow가 없어야 합니다. PC판 코트는 최대 약560CSSpx 폭, 오른쪽 기록·스킨·가이드 약300px.
- 처음은 ready, 점수0/목숨3/stage1/32개. `임무 시작`은 playing/attached로 진입, 코트에 초점을 줍니다. 그 버튼 클릭이 공 발사로 전파되지 않습니다. 별도 `공 발사` 또는 코트 클릭/Space로 명시적으로 발사합니다.
- PC: 코트 위 마우스 좌우 이동, 클릭 또는 Space 발사. 추가 접근성 조작 ←/→ 또는 A/D. 게임 코트에 초점이 있을 때만 방향키/Space 기본 스크롤을 막고 Ctrl/Alt/Meta 조합은 막지 않습니다. P/Escape 일시정지/명시적 재개.
- 모바일: 코트 **하단 35% 영역**에서 시작한 primary pointer만 패들 조작. CSSpx→논리px 환산. 드래그와 탭을 구분하고 이동8CSSpx 초과는 발사가 아닙니다. attached에서 짧은 탭(350ms 이내) 또는 별도 발사 버튼으로 발사합니다. 코트 밖 스크롤은 유지합니다.
- pointercancel/lostpointercapture/추가 손가락(코트 밖 포함)/blur/visibilitychange에서 입력을 해제합니다. 다중 터치 추가는 page capture에서 관찰하되 게임 비활성 상태 때문에 관찰 자체를 건너뛰지 않습니다.
- blur/탭 숨김/pagehide는 공·패들·진행·효과를 pause하고 stale keys/drag/RAF dt를 초기화합니다. 복귀해도 자동 재개하지 않고 `계속하기`를 요구합니다. 멈춤 중 좌표·점수·목숨이 변하지 않습니다.
- 새 임무/홈은 진행 중 또는 일시정지된 판에서 확인 UI로 보호합니다. 확인 UI는 게임 입력이 배경으로 전달되지 않으며 열릴 때 pause, 취소하면 기존 공/점수/단계를 보존한 paused 상태로 남아 `계속하기`로 재개합니다. ready/finished는 확인 없이 이동·새판 가능. 확인 대화상자는 초점 trap과 원래 버튼으로의 복귀를 구현합니다.
- 결과: 완료/목숨 소진/사용자 종료 이유, 현재판 점수, 개인 최고 여부, 최고 기록, `다시 도전`, `게임 목록`을 제공합니다. 결과 저장은 한 번만, 새판은 현재판만 초기화합니다.

## 5.1 v1.1 확정 보완 — 누적 기록·중도 종료 (G016-DQ-01)

- `plays`는 **결과가 확정된 판 수**입니다. 단순 ready 표시/임무 시작만으로 늘리지 않습니다. 시작한 판의 승리·목숨 소진·확인한 중도 종료(새 임무/홈)는 각1회 집계합니다. ready에서 시작하지 않고 새판/홈, 확인창 취소, pause/blur, 이미 저장한 결과 재표시/reload는 증가시키지 않습니다.
- `wins`는 3스테이지를 모두 완료한 결과에서만1 증가합니다. 자발 종료는 승리/목숨소진 패배로 오인하지 않습니다. 화면의 '임무 완료'는 wins를 표시합니다.
- `bestStage`는 **결과가 확정된 판에서 진입했던 최고 스테이지(도달 단계)**입니다. 기본0, 시작한 판을 stage1에서 중단하면1, stage2 진입 직후 중단하면2입니다. 통과 횟수가 아닙니다.
- `totalBricks`는 **해당 판에서 실제 제거한 모든 벽돌의 수**를 결과 시 한 번만 누적합니다. stage별32개이므로 stage2 진입 즉시 종료는32개, stage3 진입 즉시 종료는64개, 승리는96개입니다. score에서 보너스를 제거하지 않은 채 벽돌 수를 역산하지 않습니다. 전체 판 누적값은 유한 안전정수로 안전하게 제한합니다.
- `bestScore`는 모든 확정 결과의 점수 최댓값입니다. 개인 최고 갱신은 새 점수가 기존 점수보다 **엄격히 클 때**만 표시하며0점/동점은 '새 기록'이 아닙니다.
- 진행/정지 중 새 임무·홈을 **확인**하면 기존 판을 `endReason:'quit'`으로 확정 → stats를1회 반영/저장 시도 → 새판 ready 생성 또는 홈 이동 순서입니다. 재시작/홈은 통과 보너스를 추가하지 않습니다. 확인 취소는 기존판을 paused로 보존하고 stats는 그대로입니다. 이미 finished이면 기존 결과를 다시 집계하지 않습니다.
- 시작하지 않은 ready에서는 `finishGame`을 통해 임의의 plays를 만들지 않습니다. 확인한 중도 종료는 실제로 시작한 playing/paused 판만 대상으로 합니다. 창/탭을 닫기 전 진행 중 판을 복원하는 기능은 첫 범위에 없고, blur/숨김은 결과가 아닙니다.
- 정상 첫 방문의 `getItem(...)===null`은 **저장값 부재**로 정상 기본값을 사용하며 저장 불가 경고를 내지 않습니다. JSON 문자열 `'null'`, 손상 JSON, 구버전은 유효하지 않은 저장 내용으로 복구 안내를 할 수 있습니다. 실제 getter/getItem/setItem 예외·저장 실패는 지속 경고와 메모리 기록을 유지합니다.
- B11의 입력 무효는 시간/이동/발사 등 경기 진행을 뜻합니다. 임무 시작/계속하기/재도전 같은 명시적 상태 전이 버튼 자체를 금지하는 뜻이 아닙니다.
- 모바일 safe-area-inset과 320px/가로667×375에서 결과·확인창 조작에 스크롤로 접근 가능해야 합니다. 모든 실제 터치 버튼은 너비와 높이 모두44CSSpx 이상입니다. 원본 벡터 키트의 배치와 달리 실제 물리 y884는 본문 고정값을 따릅니다.
