## 1. 결함과 원인
- D1: 저장 실패 뒤 저장소가 복구되어 다른 저장 트리거(음소거/테마 적용)가 성공해도 `#result-save` 가 "기록을 저장하지 못했어요..." 로 남음.
- 원인: `main.mjs` 의 `saveNote` 는 정산(`settleResult`) 시점에만 정해지고, 이후 `persist()` 결과로는 갱신되지 않았음. `persist()` 는 전체 기록(정산된 승리 포함)을 저장하므로 성공하면 결과 기록도 실제로 저장된 것임.
- 같은 원인의 쌍둥이 증상(S3, 수정 전 재현됨): 정산 저장은 성공한 뒤 나중 쓰기가 실패하면 `기록을 저장했어요` 와 상단 실패 경고가 동시에 표시되어 모순.

## 2. 수정 (최소, `public/games/19-pegs/main.mjs` `persist()` 한 함수)
- 쓰기 성공 시 `saveNote === 'failed'` 이면 `'saved'` 로, 쓰기 실패 시 `saveNote === 'saved'` 이면 `'failed'` 로 맞춘다.
- `none`(기록 변동 없음) / `cap` / `unavailable` 문구는 건드리지 않는다. 변동 없음이 사실이고, cap/읽기 불가는 쓰기 성공으로 해소되지 않기 때문.
- 설계 판단(PM 확인 요청): saved 후 설정 쓰기만 실패하는 경우 결과 문구를 `실패` 로 내려 상단 경고와의 모순을 없앴다. 이때 방금 클리어 기록은 앞서 저장돼 있으므로 문구가 보수적(실제보다 비관적)이다. 반대안(`저장했어요` 유지)은 실패 경고와 동시에 표시되어 계약 교훈 3(경고와 모순 금지)에 걸려 채택하지 않았다.
- 새 문구, 새 상태, 타이머, 의존성 없음. QA 관찰(✕/● 대비, 경고 시 보드 이동, hover) 미변경.
