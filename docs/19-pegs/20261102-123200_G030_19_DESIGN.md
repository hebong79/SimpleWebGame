## 1. 규칙

### 1.1 판
- 엔진은 일반 격자 `{width,height,holes[]}`(holes = 판에 없는 칸)로 판을 정의한다. 칸 번호는 `i = r*width + c`(r,c는 0 시작).
  - `cross5`: 5×5에서 네 모서리(0,4,20,24)를 뺀 21칸. 이번 콘텐츠 10단계는 모두 `cross5`.
  - `cross7`: 7×7 표준 십자판 33칸. 제외 칸 = 0,1,5,6,7,8,12,13,35,36,40,41,42,43,47,48(각 모서리 2×2). 엔진/단위 시험에서만 지원하고 이번 첫 제작 UI에는 노출하지 않는다(결정 필요 3).
- 칸 상태: 돌(1) / 빈 구멍(0) / 판 밖(-1). 판 밖은 DOM에서 `aria-hidden` 빈 자리만 되고 초점·클릭 대상이 아니다.

### 1.2 점프
- 점프 = (출발 f, 도착 t). 합법 조건을 모두 만족해야 한다.
  1. f에 돌이 있다.
  2. t는 f와 같은 행이거나 같은 열이고 거리가 정확히 2칸(상·하·좌·우)이다. 대각선, 1칸, 3칸 이상, 같은 줄이 아닌 칸은 모두 불법.
  3. f, 중간 칸 m, t가 모두 판 안의 칸이고 m에 돌이 있다(빈 중간 칸 불법, 판 밖 도착 불법).
  4. t는 빈 구멍이다.
- 합법 점프의 효과(원자적): f 비움, m 비움(돌 제거), t에 돌. 말 수가 정확히 1 감소.
- 불법 입력(엔진 `tryJump`)은 상태를 바꾸지 않고 `{ok:false, reason}`만 돌려준다. reason 값: `phase`, `no-peg`, `bad-geometry`, `off-board`, `no-middle`, `occupied`.
- UI는 불법 도착 칸을 후보로 표시하지 않으므로 사용자 입력으로 불법 점프가 엔진에 전달될 수 없으나, 엔진은 독립적으로 거부해야 한다(QA oracle이 직접 호출).

### 1.3 선택·도착 상호작용
상태 `selected`(돌 칸 번호 또는 null), `targets`(selected의 합법 도착 칸 목록, 엔진이 매번 계산).
| 현재 | 입력 대상 | 결과 |
|---|---|---|
| 선택 없음 | 돌 | 그 돌 선택, 후보 도착 칸 표시. 후보 0개면 선택은 되지만 안내 `이 돌은 뛸 곳이 없어요`. |
| 선택 없음 | 빈 구멍 | 안내 `먼저 움직일 돌을 고르세요`. 상태 불변. |
| 선택됨 | 같은 돌 | 선택 해제(재탭 토글). |
| 선택됨 | 다른 돌 | 선택 교체(후보 갱신). |
| 선택됨 | 후보 구멍 | 점프 실행. 선택 해제, 커서(초점)는 도착 칸. |
| 선택됨 | 후보가 아닌 빈 구멍 | 안내 `그곳으로는 뛸 수 없어요`. 선택 유지. |
| 어디서나 | 판 밖 자리/보드 배경 | 무시. |
- 후보 구멍에 포커스 또는 `(hover: hover)` 환경의 마우스 hover가 있으면 그 점프로 제거될 중간 돌에 `제거 예정` 표시(테두리+보조 기호 `✕`)를 한다. hover 미리보기는 실제 hover 지원일 때만 적용한다(17번에서 합성 mouse hover가 늦게 도착해 유휴 DOM 변경이 생긴 전례).
- 점프 실행/선택 교체/해제 외에 보드 상태를 바꾸는 입력은 없다. 힌트 기능은 없다(원안 범위 밖).
- phase가 playing이 아닐 때(ready/paused/result, 모달 열림) 모든 칸 입력은 무시한다.

### 1.4 되돌리기(무제한)
- `history`는 점프 목록(f,m,t). 되돌리기 = 마지막 점프를 역으로 적용(t 비움, f와 m에 돌). 선택은 해제된다.
- 히스토리가 비어 있으면 no-op(상태·undoCount 불변, 기록 쓰기 없음).
- 유효한 되돌리기마다 `undoCount += 1`(그 판의 사용 수, 상한 1,000,000에서 고정). 한계는 없다.
- 승리 결과 이후 되돌리기는 금지한다(정산 1회 보호). 막힘 결과에서는 허용되며 playing으로 복귀한다(결정 필요 1).
- `처음부터`는 같은 단계의 초기 배치로 되돌리고 history 0, undoCount 0, 선택 해제. 새 round로 취급한다(round id 증가, 정산 플래그 초기화).

### 1.5 종료 판정
- 점프/되돌리기 직후 엔진이 판정한다: 말 수 == 1 → 승리. 말 수 > 1 이고 `legalJumps`가 비어 있음 → 막힘. 그 외 진행.
- 시작 배치는 항상 합법 점프 ≥ 1이고 말 수 ≥ 2(콘텐츠 검증으로 보장), 되돌리기로 시작 배치로 돌아가도 같다.
- 승리/막힘은 엔진 호출의 같은 원자적 처리에서 확정되고 결과 phase로 전환한다. 애니메이션 콜백에 규칙을 의존시키지 않는다.

### 1.6 정산과 기록
- 한 round의 승리 정산은 정확히 1회(`round.winSettled`). 한 번 승리한 round는 결과에서 되돌리기 불가이므로 재정산 경로가 없다.
- 승리 정산: 해당 단계 `clearCount += 1`, `bestRemaining = 1`, `bestUndos = min(기존, 이 round의 undoCount)`(참고 기록, 판정·해금과 무관), 전체 `completed += 1`, 다음 단계 해금(최대 10).
- 막힘 정산: 해당 단계 `bestRemaining = min(기존, 남은 말 수)`만 갱신하고 개선될 때만 쓰기. 클리어 수·해금은 올리지 않는다. 막힘 후 되돌려 다시 막혀도 같은 규칙(멱등)이라 중복 카운트가 없다.
- 포기(진행 중 홈/처음부터/단계 선택/새로 고침)는 정산하지 않는다. 미완료 보드는 저장하지 않는다.
- 누적 상한 1,000,000. `clearCount`, `completed`, `bestUndos`는 연관 필드이므로 포화 시 일부만 올라가는 정산은 금지한다(포화이면 승리 정산 전체를 no-op으로 하고 경고 `기록 한도에 도달했어요`를 지속 표시).

### 1.7 해금
- 1단계는 기본 해금. 단계 n 승리 시 n+1 해금(10단계 이후는 `모든 단계 완료` 표시). 준비 화면에서는 해금된 단계만 선택 가능하다(잠김은 `aria-disabled` + 잠김 표시).

## 2. 상태기계와 진행

```
ready --시작--> playing --정지/모달/보호--> paused --명시적 재개--> playing
playing --승리/막힘--> result
result(막힘) --한 수 되돌리기--> playing
result --다시 도전/다음 단계--> playing(새 round)   result --단계 선택--> ready
ready/result --홈--> 이동   playing/paused --홈--> 확인 모달 후 이동
```
- phase: `ready | playing | paused | result`. paused일 때 `pauseCause`: `manual | protect`(그 외 null). 모달 중 하위 정보는 `modal`(null 또는 `help|settings|confirm-home|confirm-restart`).
- `ready`: 단계 선택(기본 선택 = 클리어 수 0인 해금 단계 중 가장 낮은 번호, 없으면 1)과 `게임 시작`. 보드는 선택한 단계의 시작 배치를 비활성(미리보기) 상태로 보여 준다. 입력은 모두 무시. 시작은 명시적 버튼(키보드 포함)만 허용한다.
- `playing`: 보드 입력 허용. 도움말/설정/진행중 홈/처음부터 확인 모달을 열면 먼저 paused(원인 manual)로 전이한다. 취소/닫기는 paused로 복귀하며 자동 재개는 없다. 재개는 `이어서하기`(manual) 또는 `게임 재개`(protect) 버튼만 한다.
- 보호정지: `blur`, `visibilitychange(hidden)`, `pagehide` 중 하나가 playing에서 일어나면 paused(protect). 모달이 열려 있으면 모달은 유지하고 원인을 protect로 승격해 닫은 뒤 paused로 남는다. ready/result에서는 정지 전이 없이 키/포인터 잔상만 초기화한다.
- 이 게임에는 논리 타이머가 없다. RAF를 쓰지 않고, 시간 기반 규칙 의존이 없다. 점프/선택 효과는 CSS transition(≤150ms) 장식뿐이며 `prefers-reduced-motion`에서 0. 타이머로 DOM을 변경하지 않는다(유휴 DOM 변경 0, 17번 hover 전례). 허용되는 유일한 타이머는 취소된 제스처 직후 합성 click 억제창(≤300ms, 4.3절)이다.
- 일시정지 중에도 보드를 가리지는 않는다(시간 압박이 없는 퍼즐이므로 가림 불필요). 단 입력·되돌리기·처음부터는 모두 막고 상태 변화는 없어야 한다.
- 상태 전이마다 키/포인터 추적 상태, 선택(selected), 후보 표시를 초기화한다. 커서(초점) 칸은 유지한다.
- 시작/재개/다음 단계/결과 전환 직후 눌려 있던 Enter/Space의 `keydown.repeat`는 새로 초점이 간 요소를 활성화하지 못한다(4.4절).

## 3. 콘텐츠 10단계

### 3.1 데이터 구조
```js
STAGES = [{ id: 1, board: 'cross5', tier: 'early', count: 4,
            pegs: [5,11,12,16],              // 시작 배치(칸 번호 오름차순)
            witness: [[12,10],[5,15],[15,17]] // 1개로 줄이는 참조 해답(출발,도착). 길이 = count-1
          }, ...]
```

- `tier`: early(1~3단계) / mid(4~7) / late(8~10). `count`는 `pegs.length`와 같아야 한다(중복 저장 일치 검사).
- `witness`는 제품 UI에서 쓰지 않는다(힌트 없음). 단위 시험과 QA가 재생 검증하는 용도의 데이터다. 엔진은 witness를 신뢰하지 않으며 시험이 엔진 `tryJump`로 재생해 확인한다.
- solver(전수 DFS+메모)는 제품에 싣지 않고 시험 파일의 도우미로 둔다(결정 필요 9). 엔진은 `legalJumps`, `tryJump`, `undo` 같은 순수 함수만 공개한다.

### 3.3 생성·검증 방법(재현 가능)
1. 생성(역방향): 시드 20261102의 mulberry32로 판의 한 칸에 돌 하나를 두고, `돌 c와 같은 줄의 두 빈 칸 b,a(c-b-a 일직선, b가 c 옆)`에 대해 `c 비움, b·a에 돌`인 역점프를 목표 말 수가 될 때까지 무작위로 적용한다. 정의상 목표 배치는 정확히 (말 수−1)번의 점프로 1개가 되므로 해답이 존재한다.
2. 선별: 말 수별 후보(각 4,000~6,000회 생성, 8대칭 정규형으로 중복 제거)에서 첫 합법 점프 ≥ 2이고 단계 간 대칭 포함 중복이 없는 것 중, 균등무작위 승률 p가 단계별 목표값(0.5, 0.35, 0.2, 0.1, 0.05, 0.03, 0.02, 0.012, 0.007, 0.004)에 로그 거리로 가장 가까운 것을 채택했다. 이는 '말이 많을수록 막다른 길이 많아지는' 난이도 곡선의 근사 지표이며, 모든 단계에서 p < 1이라 일부 수순은 막힘으로 끝난다.
3. 정방향 검증(독립 구현 2종): (a) `gen.mjs` 25비트 상태 DFS+메모(`info`), (b) `verify.mjs` 2차원 배열+문자열 키 DFS. (b)는 (a)와 코드를 공유하지 않는다. 10개 모두 풀이 가능, witness를 (b)로 재생해 매 점프 말 수 −1과 합법성, 최종 말 1개 확인, 대칭 8종 중복 없음, 구간별 말 수 범위(early 4~6, mid 7~10, late 11~16), 시작 합법 점프 ≥ 1을 확인했다. 결과 `artifacts/g030-design19/verify.log`: `ALL PASS`.
4. 제품 시험(builder/QA)이 지켜야 할 검증: 3.1의 각 단계에 대해 (i) `count == pegs.length`, 칸 범위/중복/판 밖 없음, (ii) 시작 말 수 ≥ 2이고 합법 점프 ≥ 1, (iii) 엔진 `tryJump`로 witness 재생 시 매 단계 합법, 마지막 말 1개, (iv) 독립 solver로 전수 풀이 가능(해답 존재), (v) 8대칭 정규형 기준 단계 간 중복 없음, (vi) 구간별 말 수 범위, (vii) 시작 배치가 이미 승리(말 1개)/즉시 막힘이 아님. 데이터가 바뀌어도 이 시험이 통과해야 한다. 다음 단계의 시작 배치는 직전 단계 승리 배치와 무관해야 한다(단계 독립).

## 4. 입력

### 4.1 마우스·터치 탭
- 단일 포인터의 `pointerdown`과 `pointerup`이 같은 칸이고 이동 거리 ≤ 8px일 때만 탭이다. 실제 80ms 이상 누름(실시계)도 즉시 클릭과 동일하게 동작해야 하며 RAF/타이머로 누름 시간을 판정하지 않는다.
- 취소 조건: 이동 > 8px, 다른 칸에서 놓음, 보드 밖에서 놓음, `pointercancel`, `lostpointercapture`, 스크롤 발생, 두 번째 포인터(보드 밖 포함) 추가, blur/hidden, phase 전이. 취소 후 정상 탭은 다음 새 포인터 시퀀스로 곧바로 동작한다(포인터 상태 누수 없음).
- 보드는 `touch-action: manipulation`(핀치/더블탭 확대 방지), 세로 스크롤은 허용(문서 스크롤을 막지 않는다).

### 4.2 WebKit 초점 가드 교훈 반영(17번 D1)
- 칸 활성화 처리(click)는 `document.activeElement === 그 칸`을 요구하지 않는다. WebKit/Safari는 버튼 클릭으로 초점을 주지 않고, 프로그램으로 초점된 칸을 누르면 blur하여 activeElement가 body가 되기 때문이다.
- 초점 가드는 키보드 합성 click(`detail === 0`)에 대해서만 쓸 수 있다. 이 게임은 `detail === 0` click도 초점 요구 없이 허용하고(스크린리더 `.click()` 호환, 결정 필요 5), 키 반복만 4.4절로 막는다.
- 탭이 성공하면 해당 칸을 커서로 삼아 `focus({preventScroll:true})`한다(탭한 칸이 곧 이후 키보드 위치).

### 4.3 억제 플래그 교훈 반영(18번 suppressClick)
- 취소된 제스처 뒤에 따라오는 합성 click은 억제하되, 억제는 시각(timestamp)을 기록한 짧은 창(취소 시각부터 ≤300ms)으로만 구현한다. 영구 boolean 억제 금지.
- 억제 해제 경로: (1) 300ms 경과, (2) 다음 `pointerdown`, (3) phase 전이, (4) 키보드 입력. 어떤 경우에도 그 뒤의 정상 탭/키보드/스크린리더 활성화는 항상 동작해야 한다.
- 억제창 동안의 키보드 활성화(detail 0, 직전 keydown이 있는 click)는 억제하지 않는다.

### 4.4 키보드
- 보드는 roving tabindex(커서 칸 1개만 tab 정지점). 방향키는 커서를 상하좌우 한 칸 이동하며 판 밖/무효 칸 쪽은 이동하지 않는다(clamp). 판 밖 자리는 건너뛰지 않는다(결정 필요 8). 문서 스크롤과 동시에 일어나지 않도록 보드 초점일 때만 방향키를 소비한다.
- `Enter`/`Space`는 네이티브 `<button>` 활성화로 1.3절 표대로 동작한다. `keydown.repeat`로 오는 활성화는 무시한다. 점프로 결과 phase에 들어가 초점이 결과 버튼으로 옮겨져도, 누르고 있던 키의 반복 이벤트가 새 버튼을 누르지 않아야 한다(새 `keydown`만 인정). 시작/재개/다음 단계/재도전 직후도 같다.
- 보드 밖 요소에서의 키는 소비하지 않는다. `Esc`: 모달이 있으면 닫기(정지 유지), 칸이 선택되어 있으면 선택 해제, 그 외 playing이면 수동 정지(결정 필요 4). 확인 모달의 동작을 Esc가 실행하지 않는다. `Backspace`/`Z` 등의 단축키는 두지 않는다(외부 키 소비 금지).

### 4.5 모달과 초점
도움말·설정·홈 확인·처음부터 확인은 모두 모달이다. 모달은 열릴 때 먼저 정지, 내부 Tab/Shift+Tab 순환, 외부 초점 유입 차단, 모달 내부 스크롤, 닫으면 열기 전 요소로 초점 복귀(없으면 커서 칸), 뒤쪽 칸으로 입력 전달 없음. 열림 중 blur/hidden은 모달을 유지하고 닫은 뒤 보호정지로 남긴다.

## 5. 화면 레이아웃(PM UI 공통 규칙 적용)

공통: 크림 `#f7f5ee`, 잉크 `#263c40`, 카드 `#fffdf8`, 외부 폰트 없는 한국어 시스템 글꼴, 최대 1100px, 760px 이하 한 열, 3px 대비 `focus-visible`, 모든 실제 버튼/링크 44×44px 이상, 320px 문서 가로 overflow 금지, reduced-motion 지원.

- ready 패널(`#ready-panel`): 단계 선택 `#stage-select`의 `.stage-option[data-stage="1".."10"]` 10개(44px 이상 버튼, 줄바꿈 가능). 각 버튼 텍스트 `N · ●K` 형식 + 상태: 클리어 `✓`, 잠김 `잠김`, 기록 `최소 남은 돌 m`. 선택된 단계는 `aria-pressed="true"`. `게임 시작`(`#start`).

- 결과 화면 전환 시 초점은 결과의 첫 버튼(승리 `다음 단계` 또는 10단계는 `다시 도전`, 막힘 `한 수 되돌리기`)으로 이동한다. 결과 전환 직후 보드는 입력 불가이며 승리 배치(1개)는 보인 채 유지한다.

## 7. 저장 스키마 `simplegames.pebble-solo.v1`

```json
{"version":1,
 "settings":{"theme":"river","muted":true},
 "records":{"completed":0,"unlocked":1,
   "stages":[{"bestRemaining":null,"clearCount":0,"bestUndos":null} /* ×10 */]}}
```
- `version` 정확히 1. `settings.theme` ∈ {`river`,`glass`,`wood`}, `muted` boolean(기본 true).
- `stages`는 길이 10 배열. 각 항목: `bestRemaining` = null 또는 safe integer, `1 ≤ v ≤ STAGES[i].count − 1`; `clearCount` = safe integer, `0..1,000,000`; `bestUndos` = null 또는 safe integer `0..1,000,000`.
- 관계: `clearCount > 0` ⇒ `bestRemaining === 1` 이고 `bestUndos !== null`. `clearCount === 0` ⇒ `bestUndos === null` 이고 `bestRemaining`은 null 또는 ≥ 2. `bestRemaining === 1` ⇒ `clearCount ≥ 1`.
- 파생값: `completed` = 모든 clearCount 합(≤ 1,000,000), `unlocked` = 1 + (clearCount > 0인 가장 큰 단계 번호), 최대 10(클리어 없음이면 1). 저장값이 파생값과 다르면 파생값으로 교정한다(교정은 메모리에서만, 읽기 시 쓰기 없음).
- 복구 규칙: JSON 파싱 실패 / null / 배열 / 원시값 / version ≠ 1 → 전체 기본값(읽기에서 쓰지 않음). `settings`의 불량 필드는 그 필드만 기본값으로 복구하고 유효한 `records`를 지우지 않는다. 단계 하나의 불량(타입, 범위, 관계)은 그 단계만 기본값으로 복구하고 다른 유효 단계는 유지한다. `stages` 길이가 10이 아니면 인덱스별로 검사하여 빠진 단계는 기본값, 초과분은 무시한다. 모르는 추가 키는 무시한다(저장은 정규 형태로 다시 씀).
- 쓰기 시점: 승리 정산 최초 1회, 막힘 정산 중 `bestRemaining`이 개선될 때, 명시적 설정 변경(테마 적용, 소리 토글). 읽기/준비/단계 선택/선택·점프·되돌리기/정지/취소/무변동 정산에는 쓰지 않는다. 다른 저장 키는 건드리지 않는다.
- 예외 처리: `localStorage` getter, `getItem` 예외 → 메모리 플레이 + 지속 경고 `기록을 불러오지 못해 이번 접속에서만 유지돼요`, 이 세션에서 쓰기 시도 금지(알 수 없는 기존 데이터를 덮어쓰지 않기 위해, 결정 필요 10). `setItem` 예외 → 메모리 값 유지 + 지속 경고, 다음 쓰기 시도에서 성공하면 경고 해제. 읽기는 성공했지만 데이터가 손상된 경우(기본값 복구)는 경고 없이 진행하고 첫 정당한 쓰기에서 정규 형태로 덮어쓴다.
- 포화: 승리 정산이 `clearCount`나 `completed`를 1,000,000 초과로 만들면 정산 전체를 no-op(부분 증가 금지)로 하고 경고를 표시한다.

## 9. 에셋 계획

- 돌/구멍/선택/후보는 CSS(`radial-gradient`, `box-shadow`, `border`)와 유니코드 기호만 사용한다. 외부 이미지·폰트·CDN 없음. 테마는 CSS 변수 3세트(`river`/`glass`/`wood`).
- 소리(WebAudio 합성, 기본 꺼짐, 사용자 제스처 후 첫 재생 때 컨텍스트 생성): 선택(짧은 고음 사인), 점프(저음 사각 '톡' + 짧은 상승), 제거(고음 틱), 승리(상승 아르페지오 4음), 막힘(하강 2음), 되돌리기(약한 역방향 톡). 모든 음은 ≤ 400ms, 정지/숨김 시 즉시 정지, 생성 실패/미지원이면 무음으로 플레이한다.
- 구현 보고에 출처·라이선스를 기록한다: 모두 이번 프로젝트에서 직접 제작(Simon Tatham의 Pegs 코드·이미지 복제 없음, 규칙만 참고). 기존 프로젝트 파일을 재사용하면 파일명을 명시한다. 홈 카드 등록(`src/client/library.ts`)은 INTEGRATE 단계 소유이며 제목 `조약돌 하나`, 장르 퍼즐, 시간 `1~5분`, 경로 `/games/19-pegs/index.html`을 사용한다.

## 10. 가정 / 결정 필요(PM 검토)

1. 막힘의 형태. 가정: 막힘은 결과 phase(`outcome:'stuck'`)로 전환하되 `한 수 되돌리기`로 같은 round를 이어 갈 수 있다(원안 '막힘 안내 + 무제한 되돌리기' + '성공·실패 결과'를 함께 만족). 대안: 결과 화면 없이 playing 안의 막힘 배너만 두고 처음부터/되돌리기를 안내(정산 단순). 대안 선택 시 막힘 정산(`bestRemaining` 갱신)은 처음부터/단계 변경 시점으로 옮기거나 폐기해야 한다.
2. 실패(막힘) 정산은 `bestRemaining` 개선만 기록하고 클리어 수·시도 수는 올리지 않는다. 시도 횟수/실패 횟수는 저장하지 않는다(원안에 없음).
3. 7×7 표준 판은 엔진과 순수 시험만 지원하고 UI 노출/콘텐츠는 없다(원안: '규칙 엔진은 지원'). UI는 5×5 전용 레이아웃으로 만든다. 7×7 시험은 빈 33칸 구조, 표준 시작(중앙 빈 구멍, 32개)의 합법 첫 점프 4개, 소규모 배치의 점프/제거를 확인한다.
4. `Esc`의 우선순위: 모달 닫기 → 선택 해제 → 수동 정지. 선택 해제 단계가 공통 계약 문구('창 닫기/정지')에서 한 단계 추가된 것이므로 불허하면 정지만 하도록 바꿀 수 있다.
5. 합성 click(`detail 0`)은 초점 요구 없이 허용한다(18번 방식, 스크린리더 호환). 17번은 초점 없는 detail 0 click을 무시했다. 불일치가 의도한 것인지 PM이 확인해 주기 바란다.
6. 후보가 아닌 빈 구멍을 누르면 선택을 유지하고 안내만 한다(모바일 오탭 보호). 뛸 곳이 없는 돌도 선택은 가능하다(안내 문구로 학습).
7. 단계 구성은 early 3(말 4/5/6) · mid 4(7/8/9/10) · late 3(12/14/16)로 배분했다. 원안은 구간별 개수를 정하지 않았다. 후반은 11~16 범위에서 12/14/16을 골랐다(11,13,15를 쓰지 않은 것은 난이도 곡선 선택일 뿐 강한 이유 없음).
8. 방향키는 판 밖 자리를 건너뛰지 않고 이동하지 않는다. 5×5 십자판에는 내부 판 밖 칸이 없어 차이가 없고 7×7에서는 UI 범위 밖이다.
9. solver는 제품에 싣지 않고 시험 도우미로 둔다(힌트 기능 없음, dead code 방지). 설계 검증 스크립트는 `artifacts/g030-design19/`에 있으나 제품 소스가 아니다.
10. 저장 읽기에서 예외가 난 세션은 쓰기를 금지한다(기존 데이터를 덮어쓰지 않음). 대신 이 경우의 경고 해제는 새로고침 뒤 읽기 성공으로만 가능하다. 공통 계약의 '복구 시 경고 해제'는 setItem 실패에 한해 적용한다.
11. 처음부터 확인: 히스토리가 있을 때만 확인 모달, 히스토리 0이면 확인 없이 선택만 해제. 홈은 playing/paused이면 항상 확인(정지 선행). 포기는 정산 없음.
12. 점프에 논리 잠금을 두지 않는다. 연속 빠른 탭 허용(각 탭은 독립 원자 처리). 17번의 120ms 잠금 같은 규칙은 없다.
13. 일시정지 중 보드를 가리지 않는다.
14. 기본 테마 `river`, 테마 이름 `river`(강돌)/`glass`(유리알)/`wood`(나무). 원안은 '2종 이상'. 3종은 CSS 변수 세트라 부담이 작다고 판단했다.
15. 플레이 시간 1~5분은 사람 체감 미검증 목표다. 자동 시험은 시간 길이를 보증하지 않는다.
16. 설계 지표 p(균등 무작위 승률)는 사람 난이도의 직접 측정치가 아니다. 실제 난이도 조정은 사람 플레이 뒤 별도 판단.
