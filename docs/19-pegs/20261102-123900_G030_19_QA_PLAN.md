## 2. 독립 oracle (제품 코드 import 금지, 인터페이스만 호출)
oracle은 builder의 `tests/`나 제품 엔진을 읽어 재사용하지 않고 설계서 1절·3절·7절에서 새로 작성한다. 제품과의 대조는 export된 순수 함수 호출 또는 `__g030Snapshot()` 값으로 한다.

### 2.1 점프 합법성 oracle
- 별도 표현(2차원 배열 + 좌표 비교)으로 `legalJumps`를 구현한다. 입력 전수: `cross5` 21칸 모든 (출발, 도착) 쌍 25×25 = 625 조합 × 임의 돌 배치.
- 배치 전략: (a) 빈 판에 돌 1~3개를 놓는 전 조합(소규모 전수), (b) 10단계 모든 시작 배치, (c) 시드 고정 무작위 배치 20,000개(밀도 10~90%).
- 단언: 제품이 허용한 점프 집합 == oracle 집합. 개별 불법 사례를 직접 `tryJump`로 호출하여 상태 불변과 `ok:false`를 확인: 대각선, 거리 1, 거리 3·4, 같은 줄 아닌 칸, 판 밖 좌표/음수/NaN, 출발이 빈 칸/판 밖 칸, 중간 칸이 빈 칸, 도착이 점유, 도착이 판 밖 칸(모서리 포함), 출발=도착. 성공한 점프마다 말 수 −1, f/m 비움, t 돌, 다른 칸 불변을 비교.
- `cross7`: 33칸 구조, 제외 칸 목록(0,1,5,6,7,8,12,13,35,36,40,41,42,43,47,48), 표준 시작(중앙 24 빈 구멍) 합법 점프 정확히 4개(`artifacts/g030-design19/check7.log`에서 설계 시 확인한 값이며 QA는 독립 재계산), 판 밖 모서리 2×2를 지나거나 도착하는 점프 거부, 소규모 7×7 배치(2~6개) 전수 대조.

### 2.2 막힘·승리 판정 oracle
- 10단계 각각의 도달 가능한 전체 상태 그래프(비트 상태 BFS)를 oracle이 만든다. 모든 도달 상태에서: 말 수 == 1 ⇒ 승리, 말 > 1 && 합법 점프 0 ⇒ 막힘, 그 외 진행. 제품의 `isStuck/isWon`(또는 결과 phase 판정)과 상태별 일치 여부를 전수 비교(대규모 단계는 도달 상태 수가 수십만이므로 BFS 전수 또는 시드 고정 샘플 200,000개).
- 도달 상태 전체에서 승리 상태의 말 위치 분포와 막힘 상태 존재(각 단계 p<1이므로 막힘 상태가 최소 1개 존재)를 확인한다.
- 시작 배치가 이미 승리/막힘이 아님, 시작 후 되돌리기로 시작 배치로 돌아가도 같음.
- 무작위 플레이 모델 대조: 단계별 시드 고정 5,000판의 임의 행동(선택/교체/해제/점프/되돌리기/처음부터 혼합)을 oracle 참조 모델과 제품 엔진에 동시 적용하여 매 스텝 `cells`, `remaining`, `selected`, `targets`, `historyLength`, `undoCount`, phase(playing/result 및 outcome)를 비교. 결과 진입 뒤에는 승리 시 되돌리기 거부, 막힘 시 `한 수 되돌리기` 허용을 단언.

### 2.3 단계 해결가능성 solver oracle
- 독립 solver 2종(비트 DFS+메모, 문자열 키 DFS)을 새로 작성하여 10단계 모두 해답 존재를 확인하고(설계 시 결과: 모두 풀이 가능, `artifacts/g030-design19/verify.log`는 참고용이며 QA 증거가 아니다), 제품 STAGES의 witness를 oracle로 재생하여 합법성·말 수 −1·최종 1개를 확인한다.
- 데이터 검증: `count == pegs.length`; 칸 범위·중복·판 밖 없음; 구간별 말 수 범위(1~3단계 4~6, 4~7단계 7~10, 8~10단계 11~16); 8대칭 정규형 기준 단계 간 중복 없음; 시작 합법 점프 ≥ 1; 시작 말 ≥ 2; `witness.length == count−1`.
- 승리 수순 수 또는 균등 무작위 승률 p가 설계 지표와 크게 다르면(예: p가 1이거나 승리 불가) 데이터 변조로 보고. 설계 표와의 배치 차이는 결함이 아니라 변경 사항으로 보고(검증 통과가 조건).
- 해결 불가능하게 만든 변형 데이터(돌 하나 이동)를 oracle에 넣어 solver가 false를 내는지 확인(solver 자체 검증).

### 2.4 저장 스키마 oracle
- 설계서 7절 표를 그대로 코드화한 독립 검증기를 만들고 입력 사례를 제품 `recoverRecord/loadRecord/saveRecord/settle*`와 대조한다. 사례 최소 목록:
  - JSON 파싱 실패, null, 배열, 문자열/숫자/불리언, 빈 객체, version 0/2/"1"/누락 → 전체 기본값, 읽기 시 `setItem` 0회.
  - `settings`: theme 미지원 값/숫자/null, muted 문자열/숫자 → 해당 필드만 기본값, 유효한 `records` 유지.
  - `stages`: 길이 0/9/11/객체/null, 단계 항목 null/배열, `bestRemaining` 0/−1/1.5/NaN/문자열/`count` 이상, `clearCount` 음수/소수/1,000,001/Infinity/safe integer 초과, `bestUndos` 음수/소수/문자열, 관계 위반(`clearCount>0` && `bestRemaining` ≠ 1, `clearCount>0` && `bestUndos` null, `clearCount==0` && `bestUndos` 숫자, `bestRemaining==1` && `clearCount==0`) → 해당 단계만 복구하고 다른 유효 단계 유지.
  - `completed/unlocked` 불일치/범위 초과 → 파생값 교정, 쓰기 없음.
  - 정산: 첫 승리, 같은 단계 재승리(`bestUndos` min, `clearCount` 증가), 10단계 승리, 막힘 개선/무개선/동값, 1단계 막힘 후 승리 순서, 포화(`clearCount`·`completed`·`bestUndos` 경계 1,000,000)에서 부분 증가 없음.
  - 예외: `localStorage` getter throw, `getItem` throw, `setItem` throw(QuotaExceeded 포함), 이후 setItem 성공 복귀. 다른 저장 키(`simplegames.*`)가 변하지 않음.
- 쓰기 횟수 단언: 읽기/준비/단계 선택/선택·점프·되돌리기·정지·취소·모달 열고 닫기에서 `setItem` 0회. 승리 정산 정확히 1회, 막힘은 개선 때만 1회, 테마 적용 1회, 소리 토글 1회.

### 2.5 기타 순수 규칙
- 상태기계 표(설계서 2절) 전이 전수: 허용되지 않는 전이 요청(ready에서 점프, paused에서 점프/되돌리기, result에서 점프, 승리 후 되돌리기, 모달 열림 중 점프)이 상태를 바꾸지 않는지.
- 보호정지 원인 승격(manual→protect), 재개 라벨 구분(`이어서하기` vs `게임 재개`)을 엔진/스냅샷 수준에서.

## 5. 합격 기준과 보고 형식
- 판정 규칙: AC1~AC27 각 항목을 PASS/FAIL/미검증으로 표기한다. FAIL급(핵심 규칙·입력·정산·저장·접근성)이 하나라도 있으면 FAIL, 관찰(정보성)과 미검증은 별도 표기하여 `PASS_WITH_LIMITATIONS`로 구분한다. 원 FAIL 로그/스크린샷은 보존하고 재검증은 새 run 폴더에서 한다.
- 시험 스크립트 자체의 오류(기대값 오기 등)는 제품 FAIL과 분리해 `attemptN-testscript-flaws/`에 보존하고 이유를 기록한다(G029 QA 방식).
- 결과 표 형식(환경별): 단언 수 / 통과 / 실패 / pageerror / console error / 외부 요청 / CSP 위반 / exit code.
- 보고서 위치: `docs/19-pegs/<KST>_G030_19_QA_VERIFY.md`(신규). 증거 루트 `artifacts/g030-qa/19/run-<KST>/`: `sha-start.json`, `sha-end.json`, `syntax.log`, `unit-test.log`, `oracle-*.mjs/.log`, `server.mjs/.log`, `chromium-pc.log`, `chromium-mobile.log`, `webkit-mobile.log`, 결과 JSON, `visual/`.

## 6. 자동 / 브라우저 / 시각 / 실물 구분 및 한계(미리 선언)
- 자동: 2절 oracle, 단위, 구문. 브라우저 자동: 3절 A~N,P와 R1~R7(Playwright Chromium/WebKit). 시각: 3절 O(스크린샷을 사람이 열어 확인; WebKit 스크린샷은 도구 CSP 소음 때문에 분리하거나 생략 가능, 생략 시 명시).
- 미검증으로 남는 항목: 실제 iOS/macOS Safari·iPhone·물리 터치 기기(Playwright WebKit은 시뮬레이션), WebKit의 실제 멀티터치/터치 스크롤 취소(합성 이벤트 또는 마우스 경로로 대체했음을 명시), 스피커 실청취·WebAudio 실제 재생 품질, 스크린리더 실사용, OS 수준 탭 전환·창 숨김(이벤트 dispatch), 사람 체감 1~5분, 난이도 곡선의 사람 체감, 운영 3116·홈 카드 통합·실제 서버 CSP(INTEGRATE/RELEASE 단계).
