## 4. 결함

### D1 (높음, WebKit 한정) 프로그램으로 초점된 칸의 첫 탭이 무시됨
- 재현(Playwright WebKit, mobile 320, 데스크톱 크기 WebKit도 동일): 1단계에서 `게임 시작` → 초점이 칸 0(코드가 `selectCell(0)`로 부여) → 칸 0(1단계 정답 칸)을 80ms 이상 마우스 클릭 또는 `touchscreen.tap` → 이동 수 0, 클리어 안 됨. 같은 칸을 반복 탭해도 계속 무시(4회 모두 delta 0, 초점은 body).
- 기대: 탭 1회 = 이동 1, 1단계 클리어. 실제: 입력 무시. 다른 칸을 먼저 누르면 초점이 이동해 이후 정상이라 불필요한 수가 늘고 별3이 어려워집니다. `재개`(`selectCell(selected)`) 직후 같은 칸 탭 등도 영향 가능.
- 원인(추정, 로그로 확인): `main.mjs`의 칸 click 핸들러가 `document.activeElement !== b`이면 반환합니다. WebKit에서는 버튼을 마우스로 눌러도 초점을 받지 않고, 이미 초점된 버튼을 mousedown하면 blur되어 activeElement가 body가 되어 click이 거부됩니다(최소 재현 페이지에서도 버튼 클릭 후 activeElement는 BODY). Chromium은 영향 없음. 같은 게이트 때문에 Safari류처럼 mousedown 초점이 없는 환경 시뮬레이션(Chromium에서 mousedown preventDefault)에서는 초점 없던 칸 탭 자체가 무시됨을 확인(`safariFocusSimulation`; 시뮬레이션이며 실제 Safari 아님).
- 증거: `attempt2-webkit-focused-cell-tap-defect/`(원 FAIL 보존), `wk/webkit-mobile-results.json`의 J 항목, 진단 로그 `wk-debug4-stage6.log`, `wk-debug6.log`, `wk-debug8.log`(4회 탭 모두 0), `wk-debug9.log`, `wk-debug10.log`(최소 페이지: webkit BODY / chromium 버튼). 재현 스크립트 `wk-debug8.mjs`.
- 제안(수정은 builder 몫): 입력 허용을 activeElement 일치가 아닌 `visible+playing+게임 초점 영역(문서/보드 내부)`으로 완화하거나, pointerdown에서 대상 칸을 명시 초점 후 판정.
