## 1. 적용 범위와 통합 계약

이 문서는 G-001의 구현 지침이며 구현 코드를 포함하지 않습니다. Node.js 24.16.0 + TypeScript 7.0.2, HTML DOM/CSS, 런타임 외부 패키지 없는 Node 정적 서버를 사용합니다. DB·계정·CDN·네트워크 API는 없습니다. 실제 설치 상태·빌드·브라우저 실행은 이 작업에서 검증하지 않았습니다.

PM이 함수명·파일명·공개 인터페이스를 최종 확정합니다. 아래 파일 경계는 책임 분리 제안이며, 이미 PM이 배정한 인터페이스와 충돌하면 **의미와 불변조건을 보존하여 PM이 조정**합니다. 엔진에 DOM·저장·음향·시간 의존성을 넣지 않는 경계는 필수입니다.

### 파일별 책임 제안

| 경로 | 책임 | 금지하는 결합 |
|---|---|---|
| `src/engine.ts` | 보드 검증, 압축/합치기/이동, 빈칸, 생성, 이동 가능·최고 타일 계산 | DOM, localStorage, WebAudio, 전역 난수/타이머 |
| `src/state.ts` | 상태전이, 원자적 턴, 점수/판당 성공·종료 플래그, 기록 이벤트 | 화면에서 규칙 재계산 |
| `src/input.ts` | 포커스 방향키, 단일 포인터, 임계값, 반복/중복 차단, blur 정리 | 보드 직접 수정 |
| `src/storage.ts` | 버전/구조 검사, 정규화, 읽기/쓰기 예외, 메모리 대체 | 외부 데이터 실행, 저장 전체 삭제 |
| `src/view.ts` | DOM 숫자/상태/모달/포커스/접근성 렌더 | 점수 또는 승패의 독자 계산 |
| `src/audio.ts` | 사용자 제스처 뒤 WebAudio, 합치기음·음소거·중단 | 외부 음원·네트워크 |
| `src/main.ts` | 위 모듈 연결, 초기 준비 화면, UI 이벤트 라우팅 | 대형 단일 파일로 규칙/저장 뒤섞기 |

| `public/assets/tiles/`, `gardens/`, `favicon.svg` | 신규 SVG 11+3+1종 | 원안 이미지 복사/외부 SVG 참조 |
| `public/js/` | TypeScript 빌드 산출물 | 소스/비밀 파일 제공 |
| `server.mjs` | Node 내장 모듈 기반 정적 파일 제공 | API/로그인/DB/디렉터리 목록/임의 파일 제공 |
| `tests/` | 엔진·상태·저장·서버 자동 검증 | 실행하지 않은 결과 기록 |

정적 서버 공개 루트는 `public/` 한 곳으로 제한합니다. 빌드 산출물을 포함한 전달 방식과 실제 명령은 builder/PM이 확정하고 실행 결과를 남깁니다. TypeScript는 개발 시 도구이며 배포된 브라우저가 npm/CDN을 호출하지 않습니다.

### PM 확정 파일/빌드 계약 (G-002~G-005)

위 표는 역할 제안이며 실제 배정 경로는 다음으로 확정합니다.
- 브라우저 모듈: `src/client/*.ts`, relative import `.js` 확장자. 공개 API는 구현 worker가 `docs/IMPLEMENTATION.md`에 기록하고 QA가 독립 import합니다.
- 서버: `src/server/index.ts` (Node 내장 모듈, PM 소유), 서버 단위테스트 `tests/unit/server.test.ts`.
- 앱 셸: `public/index.html`, `public/style.css`, script URL `/scripts/main.js`.
- 아트 계약: `/assets/tiles/tile-<값>.svg`, `/assets/gardens/{seed,grove,bloom}.svg`, `/assets/favicon.svg`.
- `npm run build`: TypeScript를 `dist/`로 컴파일하고 `public/`를 `dist/public/`에, 컴파일된 client 모듈을 `dist/public/scripts/`에 복사합니다.
- `npm start`: `node dist/src/server/index.js`; 이 서버는 `dist/public/`만 제공합니다. 개발 문서·TS 원본·테스트·DB는 공개하지 않습니다.
- `npm test`: 실제 빌드 후 `node --test dist/tests/unit/*.test.js`. 브라우저는 `npm run test:e2e` (Playwright).
- 테스트 포트 3102, 사용자 플레이 기본 포트 3101. 기본 loopback, LAN 바인딩은 사용자가 명시적으로 `--host 0.0.0.0`를 선택할 때만 가능하며 이번 작업에서 실행하지 않습니다.
- 생성 난수는 row-major 빈칸 배열에 위치 난수 → 값 난수 순서로 생성당 2회, no-op은 0회로 고정합니다.
- 단위테스트를 위한 순수 모델 함수와 실제 UI·입력 검증을 구분하며 공개 debug 상태 주입 인터페이스는 만들지 않습니다.

## 2. 순수 엔진 모델과 불변조건 [AC-R01~R08]

### 입출력 의미 — 함수명 미지정

- 기본 타입은 `Board = number[][]`, `Direction = 'up' | 'down' | 'left' | 'right'`입니다.
- 방향 이동 연산은 원본 보드와 방향을 받아 **생성 전 새 보드**, 변경 여부, 점수 증가량, 합치기 수 또는 합치기 정보를 반환할 수 있어야 합니다. PM이 최종 반환 필드를 정합니다.
- 생성 연산은 보드와 주입된 난수원을 받아 빈칸 하나에 2/4를 놓습니다. 방향 이동과 생성은 테스트에서 분리할 수 있어야 합니다.
- 보드의 이동 가능 여부, 최대값, 유효성 검사가 독립적으로 테스트 가능해야 합니다.
- 난수원은 [0,1) 값의 순서를 주입할 수 있어야 합니다. 빈칸 순서는 행 우선 등 일관된 규칙을 정하고 문서화합니다. `floor(r × 빈칸 수)`로 균등 선택합니다. 생성당 위치/값 난수 각각 1회, 총 2회를 사용하도록 통합 계약을 권장합니다. 실제 순서가 다르면 PM이 테스트와 함께 확정합니다.
- 새 판은 빈칸 16개에서 생성 2회를 수행합니다. 방향 이동 no-op은 난수원을 호출하지 않습니다. 빈칸 없는 생성 시도는 보드를 바꾸지 않고 호출자 오류를 드러내며 임의 타일을 덮어쓰지 않습니다.

### 필수 불변조건

1. 보드는 정확히 4행×4열이며 행 배열을 공유하지 않습니다. 값은 0 또는 2 이상의 2의 거듭제곱인 안전 정수입니다. 음수·소수·문자열·NaN·Infinity를 허용하지 않습니다.
2. 이동 연산은 원본을 변경하지 않고 새 보드/행을 반환합니다. 합치기 전후 타일 값의 총합은 같습니다. 생성 후에는 생성한 2 또는 4만큼만 증가합니다.
3. 같은 이동에서 타일은 최대 1회 합칩니다. 합쳐진 결과를 다음 원소와 다시 합치지 않습니다. 점수 증가량은 합치기 결과값의 합입니다.
4. 변경 여부는 생성 전 보드와 입력 보드 비교로 판정합니다. no-op의 점수 증가량·합치기 수는 0이며 생성·음향·누적 이동 이벤트도 없습니다.
5. 이동 가능은 빈칸 존재 또는 수평/수직 동일 인접 쌍 존재입니다. 보드가 꽉 찼다는 사실만으로 패배하지 않습니다.
6. 방향별 줄 추출·역전·재배치가 대칭이어야 합니다. 동일 입력과 동일 난수열은 테마·음소거에 관계없이 같은 결과를 냅니다.
7. 2048은 승리 문턱이지 최대 값이 아닙니다. 4096 이상도 실제 숫자로 표현하며 최상위 아트를 재사용합니다. 안전 정수 범위를 넘는 비현실적 입력/계산은 오류로 거부하고 기존 상태를 보존합니다. 부정확한 수로 저장하지 않습니다.

## 3. 상태 모델·원자적 처리

### 런타임 상태 의미

- 기본 단계: `ready`, `playing`, `paused`, `won`, `over`입니다. 모달 종류(`help`, `gardens`, `restartConfirm`)와 복귀 상태를 별도로 보관할 수 있습니다.
- 판 상태: 보드, 현재점수, 현재 판 최고 타일, 유효 이동 수, 최초 성공 처리 여부, 막힘 처리 여부, 판 시작 시 최고점입니다.
- 보조 상태: 입력 잠금, 렌더/피드백 세대 토큰, 활성 포인터 ID/시작좌표, 누른 키, 문서 가시성, 이탈 후 명시적 재개 필요 여부입니다.
- 영구 프로필과 판 상태는 분리합니다. 진행 보드를 프로필에 저장하지 않습니다.
- 새 판 확정은 기존 효과/입력을 폐기하고 빈 보드에 2회 생성한 뒤 점수0·판당 플래그 초기화·시작수+1·초기 최고 타일 기록을 한 번에 반영·저장합니다. 취소/준비/reload는 이 처리를 호출하지 않습니다.
- 시작/재개/계속하기 뒤에는 보드 초점을 명시적으로 복구합니다. 유효한 보드 pointerdown에서도 보드에 초점을 주어, 포커스 제한 때문에 정상 스와이프가 무시되지 않게 합니다.

### 한 턴 트랜잭션

1. `playing`·보드 포커스·문서 보임·창 활성·입력 잠금 해제를 확인합니다. 부적합 입력은 즉시 종료합니다.
2. 순수 이동 결과를 계산합니다. no-op이면 종료합니다. RNG/저장/효과를 호출하지 않습니다.
3. 점수 증가, 한 번 생성, 현재 최고 타일 계산을 같은 동기 처리 구간에서 끝냅니다.
4. 프로필에 유효 이동 +1, 획득점수 증가량, 최고점/역대 최고 타일/해금을 반영합니다.
5. 최초 2048 달성을 판당 1회 처리하여 성공 플래그/달성 판 수를 반영하고, 막힘이면 종료 플래그/막힘 판 수를 판당 1회 반영합니다. 두 플래그는 서로 배타적이지 않습니다.
6. 보드·판·프로필을 함께 확정하고 저장을 시도합니다. 저장 실패는 턴을 되돌리지 않으며 메모리 상태를 유지합니다.
7. 성공 신규 발생이면 `won`을 우선 표시합니다. 막힘도 참이면 계속하기를 비활성화하고 결과 보기로 `over` 전환합니다. 신규 성공이 없고 막힘이 참이면 바로 `over`입니다(이미 성공 처리한 판도 동일합니다). 이미 성공했어도 이동 가능하면 `playing`을 유지합니다.
8. 최종 상태를 렌더하고 합치기가 있을 때만 시각/음향 피드백을 냅니다. 성공/결과가 보이면 게임 입력은 차단됩니다.

성공/종료 기록은 판정 순간에 처리하므로 축하/결과창 열기·닫기·재렌더·재개가 중복 집계를 일으키지 않아야 합니다. 한 번 끝난 판에서 게임 입력은 무효입니다.

### 애니메이션·이탈 경쟁 조건 [AC-F03~F06]

- 합치기 효과는 최대 120ms 표시용입니다. 지연 콜백으로 생성/득점/승패/해금을 처리하지 않습니다.
- 효과 중 입력은 무시하며 큐를 두지 않습니다. effect token을 통해 재시작 이전 콜백이 새 판을 건드리지 못하게 합니다.
- pause/blur/hidden에서 모든 피드백 타이머·프레임을 취소하고 이미 확정된 최종 보드를 표시합니다. WebAudio 예약음을 중단하고 입력 잠금을 정리하되 paused/requiresResume으로 게임 입력은 막습니다.
- 재개 때 오래된 효과를 재생하거나 남은 키/스와이프를 적용하지 않습니다. keyup을 받지 못한 경우도 누른 키 집합을 비워 안전하게 복구합니다.
- 모달 중 이탈하면 모달을 덮어 버리지 않습니다. 기존 복귀 경로에 재개 필요 플래그를 표시하여, 모달 종료 후 곧바로 플레이가 되지 않게 합니다.
- 모달 닫기·재개·재시작 클릭/키 이벤트를 소비하고 게임 핸들러에 전달하지 않습니다. 포인터 완료 이벤트는 모달 열기/닫기 경계를 넘어 재사용하지 않습니다.

## 4. 입력 설계 [AC-I01~I05]

### PC

- 보드에 명시적 포커스와 접근 가능한 이름을 부여합니다. 방향키는 보드 자체가 입력 대상일 때만 처리합니다. 설정/버튼/텍스트 입력 대상에서는 처리하지 않습니다.
- 처리하는 Arrow 키에만 `preventDefault`를 적용합니다. 문서 전체의 키/스크롤을 차단하지 않습니다.
- `KeyboardEvent.repeat`와 누른 키 집합으로 자동 반복을 막습니다. keyup·blur·hidden·pause·모달 전환에서 집합을 초기화합니다.
- Esc는 게임 맥락의 최상위 모달을 닫거나 플레이를 정지합니다. 축하/결과를 승인하거나 재시작을 확정하지 않습니다. paused에서 Esc로 재개한다면 반드시 명시적 사용자 입력으로 취급하고 상태를 검증합니다.
- 모달에 초점 이동/내부 Tab 순환/닫은 뒤 복귀를 제공합니다. 버튼의 Enter/Space 기본 동작을 방향키처럼 보드에 전달하지 않습니다.

### 모바일/포인터

- Pointer Events 계열로 단일 경로를 사용하여 touch와 mouse의 이중 이벤트를 만들지 않습니다. 보드 시작 시 primary pointer ID·CSS px 좌표를 저장합니다.
- pointerup에서 `max(abs(dx), abs(dy)) >= 24`와 축 우세를 확인하고 정확히 한 방향 입력을 생성합니다. `dx=24,dy=0`은 오른쪽, `dx=23,dy=0`은 무효, `dx=24,dy=24`는 무효입니다.
- 다중 포인터 시작 시 진행 제스처를 취소하고, pointercancel·lostcapture·모달·정지·이탈에서도 초기화합니다. 앱 상태가 달라졌으면 pointerup을 폐기합니다.
- `touch-action` 제어는 보드 영역으로 한정합니다. 페이지/설정 창은 정상 스크롤을 유지합니다. 이미지 드래그·텍스트 선택·컨텍스트 메뉴가 보드 제스처를 방해하지 않게 하되 페이지 전체 확대를 금지하지 않습니다.

## 5. 저장 스키마·검증·복구 [AC-D01~D05]

### 프로필 의미

권장 키는 `number-garden:profile:v1`이며 객체 내부 `version: 1`도 검사합니다. 아래는 데이터 필드 명세이지 실제 저장 파일이 아닙니다.

| 필드 | 타입/기본값 | 의미/검사 |
|---|---|---|
| `version` | 정수 / 1 | 정확히 지원하는 버전만 허용합니다. |
| `bestScore` | 안전한 비음수 정수 / 0 | 역대 최고점입니다. |
| `bestTile` | 0 또는 2 이상 2의 거듭제곱 / 0 | 역대 최고 타일입니다. |
| `gamesStarted` | 안전한 비음수 정수 / 0 | 명시적 판 시작 수입니다. |
| `gamesFinished` | 안전한 비음수 정수 / 0 | 막힘 확정 판 수, `<= gamesStarted`입니다. |
| `gamesWon` | 안전한 비음수 정수 / 0 | 최초 2048 달성 판 수, `<= gamesStarted`입니다. |
| `totalMoves` | 안전한 비음수 정수 / 0 | 유효 이동 합입니다. |
| `totalScore` | 안전한 비음수 정수 / 0 | 이동별 획득점수의 누적 합, `>= bestScore`입니다. |
| `unlockedGardens` | 허용 ID 배열 / `[seed]` | 중복 없이 bestTile에 따른 정규화 결과를 보관합니다. |
| `selectedGarden` | 허용 ID / `seed` | 해금 집합에 있어야 합니다. |
| `muted` | boolean / true | 음소거 설정입니다. |

- `gamesWon + gamesFinished <= gamesStarted`는 검사하지 않습니다. 성공 후 막힘으로 끝난 동일 판은 양쪽에 포함됩니다.
- 해금은 `{seed} + bestTile>=256이면 grove + bestTile>=1024이면 bloom`으로 유도합니다. 저장된 문자열만 믿어 잠금을 풀지 않습니다. 유효한 최고 타일에서 유도한 해금은 유지하고, 알 수 없는 ID·중복·조건 미달 해금을 제거합니다. 잠기거나 없는 선택은 seed로 복구합니다.
- 필수 숫자·버전·객체 구조가 잘못되면 프로필 전체를 기본값으로 복구합니다. 테마/음소거 같은 선택 필드만 잘못되면 유효한 핵심 기록을 유지하고 해당 필드를 기본값으로 정규화합니다. 모르는 필드는 가져오지 않습니다.
- JSON 입력은 허용 필드만 새 객체에 복사합니다. 사용자 객체를 앱 상태/DOM에 통째로 merge하지 않습니다. 문자열 길이/배열 길이를 제한하고 과도한 저장 데이터는 거부합니다(권장 원문 16KiB 상한).
- 프로필의 숫자 범위·교차 조건을 먼저 검사합니다. 무한대/과대 수를 절삭해 정상 데이터인 것처럼 취급하지 않습니다. 저장 전에도 동일 검사를 통과해야 합니다.

### 쓰기 시점·오류

- 판 시작 확정, 모든 유효 이동, 정원 적용, 음소거 변경, 최초 성공/막힘 트랜잭션 확정에 저장합니다. 한 이동의 여러 변경은 한 번의 프로필 쓰기로 묶습니다.
- 결과 표시 때 현재점수를 누적 합에 다시 더하지 않습니다. 재시작은 프로필을 초기화하지 않습니다. reload는 새 판을 자동 시작하지 않습니다.
- 읽기(`getItem`)·파싱·쓰기(`setItem`)를 각각 예외 처리합니다. Storage 접근 자체가 예외를 내는 환경도 포함합니다. 쓰기 실패 후 앱은 메모리 모드로 진행하고 눈에 띄는 저장 불가 안내를 유지합니다.
- 손상 복구 성공 시 게임 전용 키만 정규화해 저장을 시도합니다. `localStorage.clear()`를 쓰거나 다른 게임의 키를 건드리지 않습니다. 과거/미지원 버전은 명시적 마이그레이션이 없는 한 기본값으로 복구합니다.
- 정상 프로필은 최고점·최고 타일·해금·누적값이 새 판/페이지 재진입으로 감소하지 않습니다. 저장소 손상/사용자 삭제/차단 상황에서는 보존을 보장하지 않는다고 안내합니다.
- 여러 탭에서의 동시 기록 병합은 첫 버전 보장 범위가 아닙니다. 가능하면 storage 변경 알림으로 중복 탭 사용을 안내합니다. 이를 계정/서버 동기화로 확대하지 않습니다.

## 6. 표시·자산·음향 경계

- 보드 논리는 항상 4×4입니다. CSS Grid와 정사각 컨테이너로 320px~PC 폭에 맞춥니다. 포인터 좌표는 CSS px의 상대 이동만 필요하므로 보드 렌더 배율과 임계값을 혼동하지 않습니다.
- 실제 숫자는 DOM 텍스트로 렌더합니다. SVG는 장식이며 누락 시에도 숫자와 게임 규칙이 유지되어야 합니다. 알 수 없는 큰 타일은 최상위 스타일과 실제 숫자를 사용합니다.
- 숫자/점수/상태는 `textContent` 등 텍스트 경로로 넣고 저장 문자열을 HTML로 해석하지 않습니다. 모달은 의미 있는 제목/버튼 이름을 갖추고 배경을 비활성화합니다.
- 감소된 모션은 효과를 제거해도 동일한 최종 상태를 제공합니다. 소리 없이도 성공/막힘/해금/저장 실패를 알 수 있어야 합니다.
- 합치기음은 짧은 oscillator와 gain envelope로 직접 합성하고 한 이동당 한 번만 재생합니다. 초기 muted=true, 사용자 제스처에서만 AudioContext 활성화를 시도합니다. 권한/지원 실패는 게임을 막지 않습니다. 음소거/정지/이탈에서 예약/재생 노드를 정리합니다.
- SVG 15개(타일 11, 정원 3, favicon 1)는 프로젝트 신규 제작으로 표시하고 출처 목록을 남깁니다. 외부 이미지·음원·폰트를 포함하지 않습니다.

## 7. 정적 서버·보안 [AC-S01~S03]

- 기본 listen 주소는 loopback으로 제한하고 포트 충돌은 오류를 명시합니다. LAN 공개·외부 배포·특권 포트/설치는 승인 없이 하지 않습니다. 실제 휴대기기 LAN 검증이 필요하면 PM에게 주소 노출 승인을 요청하며 에뮬레이션 결과와 실기기 결과를 구분합니다.
- GET/HEAD 정적 자산만 제공합니다. 그 외 메서드는 405, 없는 파일은 404로 응답하고 디렉터리 목록을 내보내지 않습니다. HEAD는 본문을 보내지 않습니다.
- 요청 URL의 query를 분리하고 경로를 안전하게 decode/검증한 뒤 공개 루트 아래 정규 경로인지 확인합니다. 잘못된 인코딩·NUL·상위 경로 탈출·역슬래시·Windows 드라이브/UNC/장치 경로·ADS 콜론·이중 인코딩을 거부합니다. 심볼릭 링크/재분석 지점도 실제 해석 경로가 루트 밖이면 거부합니다. 보수적인 자산 확장자/경로 허용 목록을 사용할 수 있습니다.
- `.env`, `.git`, 소스·문서·임의 프로젝트 밖 파일을 제공하지 않습니다. `Content-Type`을 확장자별로 설정하고 `X-Content-Type-Options: nosniff`를 사용합니다. 오류에 로컬 경로/스택/비밀을 노출하지 않습니다.
- 외부 연결이 필요 없으므로 CSP는 자체 스크립트/스타일/이미지로 한정하고 connect/object/frame 등을 제한하는 방향으로 구성합니다. 인라인 스크립트·eval·SVG script·외부 참조를 사용하지 않습니다. CSP와 실제 동적 표시 방식은 builder가 함께 검증합니다.
- 사용자 텍스트를 HTML/스크립트/파일 경로로 실행하지 않습니다. 테마 ID는 상수 허용 목록에서 자산 경로로 매핑합니다. 저장 값으로 임의 URL을 생성하지 않습니다.

## 8. 검증 전략·통합 경계

1. **자동 엔진 테스트:** 4방향 고정 벡터·원본 불변·타일 합 보존·주입 난수 경계·no-op 난수 미호출·막힘·2048/4096입니다.
2. **자동 상태/저장 테스트:** 최초 성공/막힘 동시 처리·중복 이벤트·재시작/정지/이탈·난수 소비·숫자/버전/소유권 검증·Storage 예외를 가짜 저장 어댑터로 검증합니다. 가짜 결과를 실브라우저 검증처럼 보고하지 않습니다.
3. **실제 빌드/서버 테스트:** TypeScript 빌드, HTTP 정상/HEAD/404/405, 루트 탈출/인코딩/Windows 경로, 런타임 패키지 불필요 여부를 실제 출력으로 남깁니다.
4. **브라우저/직접 입력:** 포커스·모달·키·포인터·탭 이탈·120ms·320px·44px·소리·저장 지속·오프라인을 확인합니다. 기기/브라우저 버전, 뷰포트, 자동/수동 구분과 증거를 남깁니다.
5. 모든 케이스의 절차와 기대 결과는 `ACCEPTANCE.md`에 있습니다. 이 문서를 작성한 시점에는 구현·빌드·플레이 테스트를 실행하지 않았습니다.

## 9. PM 통합 확인 사항

- 함수명·파일명·타입 반환 필드·난수 호출 순서는 PM이 확정하여 builder/QA에 동일하게 전달해야 합니다.
- 정원 문턱(기본/256/1024), 음소거 초기값 true, 진행판 미저장, 초기 성공+막힘 우선순위는 이 설계의 명시 결정입니다. 원안의 미정 영역을 구체화한 것이며 외부 조사 사실이 아닙니다.
- 기존 project.json/BACKLOG/DECISIONS/HANDOFF는 planner 수정 범위 밖입니다. PM이 확정값과 이후 실제 검증 상태를 반영해야 합니다. 보드 게시·추가 산출물 생성도 본 worker 범위 밖입니다.
